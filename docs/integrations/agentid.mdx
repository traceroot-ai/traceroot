Let an AI agent sign in to traceroot as itself, with its own AgentMail inbox, into an account of its own.

- **Sign-in:** [app.traceroot.ai/auth/sign-in](https://app.traceroot.ai/auth/sign-in), then **Continue with AgentID**, through OpenID Connect
- **Available on:** traceroot Cloud, and a self-hosted traceroot once it is [turned on](#self-hosting)
- **Listing:** [traceroot in the AgentID directory](https://www.agentid.com/apps/traceroot)

[AgentID](https://www.agentid.com) is AgentMail's sign-in service for AI agents. It turns an agent's AgentMail inbox into an account login, so an agent can hold its own traceroot account, apart from yours.

The account belongs to the inbox. Signing in again with the same inbox returns to the same account. A different inbox is a different account.

## When to use it

- **An agent with its own login.** The agent signs in as itself, and your own login stays with you.
- **Work that continues across sessions.** A scheduled worker or a long-running coding agent signs back in and returns to the same account.
- **Agent accounts kept apart from people's.** traceroot keeps an agent's account separate from every existing account, including one registered with the same email address.

## Requirements

- An AgentMail inbox for the agent, and permission to authorize its sign-in. [AgentID Sign-In](https://docs.agentmail.to/agentid-sign-in) in the AgentMail docs covers setting both up.

## Sign in

1. Open [app.traceroot.ai/auth/sign-in](https://app.traceroot.ai/auth/sign-in) and choose **Continue with AgentID**.
2. Continue with the agent's inbox and approve the sign-in, as the AgentID guide describes.
3. After approval, the browser returns to traceroot, signed in, with the agent's inbox address as the account email.

Signing in gives the agent an account. Access to a project's data is separate, and the next section covers it.

## Work in your team's project

To let the agent work in a project your team already has, create a project API key in that project's settings and give it to the agent. The key is scoped to that one project. [Workspaces, projects, and access](/getting-started/concepts) explains roles and keys.

## Use traceroot from the terminal

With a project API key, the agent can use the traceroot CLI right away:

```bash
npm install -g traceroot-cli

export TRACEROOT_API_KEY="tr-..."

traceroot traces list
```

`traceroot status` shows who the current credential belongs to and where it came from. [Authentication and Configuration](/cli/authentication) explains how the CLI chooses between a browser login and an API key.

## What traceroot receives

traceroot requests the `openid`, `email` and `profile` scopes.

| Claim | Used for |
|-------|----------|
| Identifier (`sub`) | Matching a returning agent to its account |
| Email | The account's email address |
| Name | The account's display name. The part of the email before `@` is used when no name is set |

## Self-hosting

Sign in with AgentID is off until both variables are set in `.env`. With both set, **Continue with AgentID** on the sign-in and sign-up pages becomes active.

```bash
AUTH_AGENTID_CLIENT_ID=your-agentid-client-id
AUTH_AGENTID_CLIENT_SECRET=your-agentid-client-secret
```

1. Create an application in the [AgentID console](https://console.agentid.com).
2. Register the callback `<BETTER_AUTH_URL>/api/auth/callback/agentid`.
3. Set **Maximum signups per owner** on the application before you turn sign-in on. AgentID enforces that cap.
4. Add the client ID and secret to `.env` and restart the web service.

## What to know

- An agent account stays separate from every other account. Signing in with AgentID never links to an existing account, including one registered with the same email address.
- A workspace invitation is accepted with a verified email address, and traceroot stores an agent's address as unverified. To give an agent access to a team's project, use a project API key.
