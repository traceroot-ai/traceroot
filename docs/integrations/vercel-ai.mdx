---
title: Vercel AI SDK
description: Trace Vercel AI SDK 7 and 6 agents in TraceRoot — no instrumentModules config required
---

Trace [Vercel AI SDK](https://ai-sdk.dev) calls — `generateText`, `streamText`, `ToolLoopAgent`, structured output, and embeddings — in TraceRoot. The AI SDK emits OpenTelemetry spans itself; TraceRoot registers the global tracer provider those spans land in and enriches them through the OpenInference span processor. No `instrumentModules` entry is needed.

<Warning>
  **AI SDK 7 emits no spans unless you install `@ai-sdk/otel` and call `registerTelemetry`.** OpenTelemetry support moved out of the `ai` package in 7.0. A working AI SDK 6 setup upgraded to 7 — or a fresh `npm install ai`, which resolves to 7.x — silently produces zero spans until you add the two lines in [Setup](#setup). `experimental_telemetry: { isEnabled: true }` on its own does nothing on 7.x.

  Older examples also use `maxSteps`, which 7.x ignores without an error: the loop stops after the first tool call and `result.text` is empty. Use `stopWhen`.
</Warning>

## Supported versions

| AI SDK | Telemetry switch | Verified with (2026-09-23) |
|--------|------------------|----------------------------|
| **7.x** (npm `latest`) | `registerTelemetry(new OpenTelemetry())` once at startup. Telemetry is then on for every call. | `ai@7.0.113`, `@ai-sdk/otel@1.0.113`, `@ai-sdk/openai@4.0.74`, `@traceroot-ai/traceroot@0.4.0` |
| **6.x** (npm `ai-v6`) | `experimental_telemetry: { isEnabled: true }` on every call | `ai@6.0.290`, `@ai-sdk/openai@3.0.117`, `@traceroot-ai/traceroot@0.4.0` |
| 5.x (npm `ai-v5`) | `experimental_telemetry: { isEnabled: true }` on every call | Not tested. Same mechanism as 6.x |

AI SDK 7 requires Node.js 22 or newer (its `engines` field) and ships as ES modules. AI SDK 6 with TraceRoot requires Node.js 20 or newer (TraceRoot's requirement). `@ai-sdk/otel` 1.0.N depends on exactly `ai` 7.0.N, so upgrade the two together; the provider package major must match `ai`'s major (`@ai-sdk/openai@^4` with `ai@^7`, `@ai-sdk/openai@^3` with `ai@^6`).

## Setup

<Tabs>
  <Tab title="AI SDK 7">
    ```bash
    npm install @traceroot-ai/traceroot ai@^7 @ai-sdk/otel@^1 @ai-sdk/openai@^4 zod@^4
    ```

    Initialize TraceRoot and register the AI SDK's OpenTelemetry integration. Either order works, but both must run before your first model call:

    ```typescript
    import { TraceRoot } from '@traceroot-ai/traceroot';
    import { registerTelemetry } from 'ai';
    import { OpenTelemetry } from '@ai-sdk/otel';

    // Registers the global OpenTelemetry tracer provider.
    TraceRoot.initialize();

    // Plugs the AI SDK's OpenTelemetry integration into that provider.
    // Without this line, AI SDK 7 emits no spans at all.
    registerTelemetry(new OpenTelemetry({ usage: true }));
    ```

    `usage: true` adds the AI SDK's detailed usage attributes (reasoning tokens) on top of the GenAI semantic-convention defaults. Once an integration is registered, every call is traced without a per-call option; pass `telemetry: { functionId }` to name a call's root span (recommended: it becomes `gen_ai.agent.name`, which older installs of the OpenInference processor need to classify the root as an agent), or `telemetry: { isEnabled: false }` to opt one call out.
  </Tab>
  <Tab title="AI SDK 6">
    ```bash
    npm install @traceroot-ai/traceroot ai@^6 @ai-sdk/openai@^3 zod@^4
    ```

    Initialize TraceRoot at your entry point, before any other OpenTelemetry SDK:

    ```typescript
    import { TraceRoot } from '@traceroot-ai/traceroot';

    // AI SDK 6 emits OpenTelemetry spans itself. TraceRoot registers the global
    // tracer provider they land in — no instrumentModules entry needed.
    TraceRoot.initialize();
    ```

    Telemetry is off by default in AI SDK 6: add `experimental_telemetry: { isEnabled: true }` to every call you want traced (see [Usage](#usage)).
  </Tab>
</Tabs>

Set `TRACEROOT_API_KEY` and your provider key (for example `OPENAI_API_KEY`) in the environment.

## Usage

The snippets use top-level `await`, which requires an ES module. In a CommonJS project, wrap them in an `async` function.

### Multi-step tool calls

<Tabs>
  <Tab title="AI SDK 7">
    ```typescript
    import { generateText, tool, isStepCount } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';

    const result = await generateText({
      model: openai('gpt-4o-mini'),
      instructions: 'You are a concise weather assistant.',
      prompt: 'What is the weather in Tokyo?',
      stopWhen: isStepCount(5),
      telemetry: { functionId: 'weather_agent' },
      tools: {
        getWeather: tool({
          description: 'Get current weather for a city',
          inputSchema: z.object({ city: z.string() }),
          execute: async ({ city }) => ({ city, temp: 72, condition: 'sunny' }),
        }),
      },
    });

    console.log(result.text);
    ```
  </Tab>
  <Tab title="AI SDK 6">
    ```typescript
    import { generateText, tool, stepCountIs } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';

    const result = await generateText({
      model: openai('gpt-4o-mini'),
      system: 'You are a concise weather assistant.',
      prompt: 'What is the weather in Tokyo?',
      stopWhen: stepCountIs(5),
      // Required on every call in AI SDK 6 — telemetry is off by default.
      experimental_telemetry: { isEnabled: true, functionId: 'weather_agent' },
      tools: {
        getWeather: tool({
          description: 'Get current weather for a city',
          inputSchema: z.object({ city: z.string() }),
          execute: async ({ city }) => ({ city, temp: 72, condition: 'sunny' }),
        }),
      },
    });

    console.log(result.text);
    ```
  </Tab>
</Tabs>

### Agents

`ToolLoopAgent` runs the same loop as `generateText` and produces the same spans. Set telemetry once in the constructor.

<Tabs>
  <Tab title="AI SDK 7">
    ```typescript
    import { ToolLoopAgent, tool, isStepCount } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';

    const agent = new ToolLoopAgent({
      model: openai('gpt-4o-mini'),
      instructions: 'You are a support triage assistant.',
      stopWhen: isStepCount(5),
      telemetry: { functionId: 'support_agent' },
      tools: {
        lookupOrder: tool({
          description: 'Look up an order by id',
          inputSchema: z.object({ orderId: z.string() }),
          execute: async ({ orderId }) => ({ orderId, status: 'shipped' }),
        }),
      },
    });

    const result = await agent.generate({ prompt: 'Where is order 1234?' });
    console.log(result.text);
    ```
  </Tab>
  <Tab title="AI SDK 6">

### Structured output and embeddings

The current structured-output API is `generateText` with an `output` setting. `generateObject` still works in both versions (deprecated since 6.0) and is traced too — see [What Gets Captured](#what-gets-captured) for its span names.

<Tabs>
  <Tab title="AI SDK 7">
    ```typescript
    import { generateText, embed, Output } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';

    const { output } = await generateText({
      model: openai('gpt-4o-mini'),
      output: Output.object({
        schema: z.object({ city: z.string(), summary: z.string() }),
      }),
      prompt: 'Summarize the weather in Tokyo.',
      telemetry: { functionId: 'weather_summary' },
    });

    const { embedding } = await embed({
      model: openai.embeddingModel('text-embedding-3-small'),
      value: output.summary,
      telemetry: { functionId: 'weather_embedding' },
    });

    console.log(output, embedding.length);
    ```
  </Tab>
  <Tab title="AI SDK 6">
    ```typescript
    import { generateText, embed, Output } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';

    const { output } = await generateText({
      model: openai('gpt-4o-mini'),
      output: Output.object({
        schema: z.object({ city: z.string(), summary: z.string() }),
      }),
      prompt: 'Summarize the weather in Tokyo.',
      experimental_telemetry: { isEnabled: true, functionId: 'weather_summary' },
    });

    const { embedding } = await embed({
      model: openai.embeddingModel('text-embedding-3-small'),
      value: output.summary,
      experimental_telemetry: { isEnabled: true, functionId: 'weather_embedding' },
    });

    console.log(output, embedding.length);
    ```

### Flushing before exit

Spans are exported in batches. In short-lived scripts and serverless handlers, flush before the process exits:

```typescript
import { TraceRoot } from '@traceroot-ai/traceroot';

await TraceRoot.flush();
```

## Next.js

Initialize from `instrumentation.ts` (project root, or `src/` if you use it) so TraceRoot is set up once, before any route runs. Verified with Next.js 16.3 on AI SDK 7 and AI SDK 6; see Vercel's [telemetry docs](https://ai-sdk.dev/docs/ai-sdk-core/telemetry) for the AI SDK side:

```typescript
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    const { TraceRoot } = await import('@traceroot-ai/traceroot');
    const { registerTelemetry } = await import('ai');
    const { OpenTelemetry } = await import('@ai-sdk/otel');

    TraceRoot.initialize();
    registerTelemetry(new OpenTelemetry({ usage: true }));
  }
}
```

For AI SDK 6, keep only the `TraceRoot` import and `TraceRoot.initialize()` inside the `register()` function, and set `experimental_telemetry` on each call.

Also mark the SDK as external in `next.config.ts`. Without this, route handlers get their own bundled copy of `@traceroot-ai/traceroot`: `TraceRoot.flush()` called from a route exports nothing and `TraceRoot.isTracingActive()` returns `false` there, and spans leave only when the batch timer fires. With the option, `flush()` exports immediately (verified on both AI SDK versions):

```typescript
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  serverExternalPackages: ['@traceroot-ai/traceroot'],
};

export default nextConfig;
```

## What Gets Captured

Span names and attributes differ by version. AI SDK 7's `OpenTelemetry` integration follows the OpenTelemetry GenAI semantic conventions; AI SDK 6 uses the AI SDK's own `ai.*` names. TraceRoot handles both. The trees below show span names as TraceRoot displays them; TraceRoot shows tool spans by tool name, whatever name the SDK emitted (`execute_tool <tool>` on 7.x, `ai.toolCall` on 6.x).

<Tabs>
  <Tab title="AI SDK 7">
    One `invoke_agent` span per `generateText` / `streamText` / agent call, a `step` span per loop iteration, and a `chat` span plus one span per tool call under each step:

    ```
    invoke_agent gpt-4o-mini          # AGENT — gen_ai.agent.name = functionId
    ├── step 1
    │   ├── chat gpt-4o-mini          # LLM — model, messages, tokens
    │   └── getWeather                # TOOL — arguments and result (emitted as execute_tool getWeather)
    └── step 2
        └── chat gpt-4o-mini
    embeddings text-embedding-3-small # embed / embedMany (root + one child per provider call)
    ```

    `generateObject` produces `invoke_agent` → `chat` with no `step` level.

    | Attribute | Where |
    |-----------|-------|
    | Model | `gen_ai.request.model` |
    | Messages and response | `gen_ai.input.messages`, `gen_ai.output.messages` on `invoke_agent` and `chat` |
    | Tool calls | `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result` on the tool span |
    | Tokens | `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` |
    | Cache read / write | `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens` |
    | Reasoning | `ai.usage.outputTokenDetails.reasoningTokens` — only with `usage: true` |
    | Cost | Calculated from token usage and model pricing |
    | Latency | Request duration per span |
  </Tab>
  <Tab title="AI SDK 6">
    Span names are `ai.<operation> <functionId>` for the wrapper and `ai.<operation>.doGenerate` / `.doStream` / `.doEmbed` for each provider call:

    ```
    ai.generateText weather_agent     # AGENT
    ├── ai.generateText.doGenerate    # LLM — model, messages, tokens
    ├── getWeather                    # TOOL — arguments and result (emitted as ai.toolCall)
    └── ai.generateText.doGenerate
    ai.streamText haiku
    └── ai.streamText.doStream
    ai.embed weather_embedding
    └── ai.embed.doEmbed
    ```

    `ToolLoopAgent` and `generateText` with `output` both appear as `ai.generateText`. `generateObject` appears as `ai.generateObject` / `ai.generateObject.doGenerate`. Inside an `observe()` wrapper the root span keeps the plain `ai.generateText` name; the `functionId` suffix is added only when it is the trace root.

    | Attribute | Where |
    |-----------|-------|
    | Model | `gen_ai.request.model` on `doGenerate` / `doStream` |
    | Messages and response | `input.value`, `output.value` (added by the OpenInference processor) |
    | Tool calls | `input.value`, `output.value` on the tool span |
    | Tokens | `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` on `doGenerate` / `doStream` |
    | Cache read / write | `ai.usage.inputTokenDetails.cacheReadTokens`, `ai.usage.inputTokenDetails.cacheWriteTokens` |
    | Reasoning | `ai.usage.outputTokenDetails.reasoningTokens` |
    | Cost | Calculated from token usage and model pricing |
    | Latency | Request duration per span |
  </Tab>
  <Tab title="AI SDK 7 (Legacy)">
    With `registerTelemetry(new LegacyOpenTelemetry())` (see [Troubleshooting](#troubleshooting)), AI SDK 7 emits the 6.x names and attributes. The one difference: the tool span (emitted as `ai.toolCall`, displayed by tool name) nests under the `doGenerate` span that requested it instead of beside it.

    ```
    ai.generateText weather_agent     # AGENT
    ├── ai.generateText.doGenerate    # LLM — model, messages, tokens
    │   └── getWeather                # TOOL — arguments and result (emitted as ai.toolCall)
    └── ai.generateText.doGenerate
    ```

    Attributes are the same as in the AI SDK 6 tab, including reasoning tokens without any extra option.
  </Tab>
</Tabs>

TraceRoot counts tokens and cost on the model-call spans (`chat`, `doGenerate`, `doStream`) only. Wrapper spans such as `invoke_agent`, `step`, and `ai.generateText` restate the totals of their children and are not priced, so multi-step runs are not double-counted. Verified by replaying captured spans through the ingest transform: stored totals equal the sum of the individual model calls for both versions.

## Troubleshooting

**No spans at all (AI SDK 7).** `registerTelemetry(new OpenTelemetry())` is missing, or `@ai-sdk/otel` is not installed. This is also what an upgrade from 6.x to 7.x looks like: the `experimental_telemetry` option still type-checks (it is a deprecated alias of `telemetry`), but nothing is emitted until the integration is registered.

**No spans at all (AI SDK 6).** The call has no `experimental_telemetry: { isEnabled: true }`. Telemetry is opt-in per call in 6.x.

**Console error: `tracer-provider registration was rejected`.** Another OpenTelemetry SDK — for example `registerOTel` from `@vercel/otel`, or a `NodeSDK` — registered the global tracer provider before `TraceRoot.initialize()`. AI SDK spans then flow to that provider and never reach TraceRoot. Initialize TraceRoot first and remove the other registration.

**Spans missing from short-lived processes.** The exporter batches spans. Call `await TraceRoot.flush()` (or `TraceRoot.shutdown()`) before exit. In Next.js, this also requires `serverExternalPackages` (see the Next.js section above).

**No reasoning tokens (AI SDK 7).** Construct the integration with `new OpenTelemetry({ usage: true })`. The GenAI defaults carry input, output, and cache counts but not reasoning tokens.

**`telemetry.metadata` does not compile (AI SDK 7).** The `metadata` field was removed in 7.0 along with `tracer`. Use `functionId` to name spans. To attach your own values, pass them as `runtimeContext: { userId }` on the call, allow-list them with `telemetry: { includeRuntimeContext: { userId: true } }`, and construct the integration with `new OpenTelemetry({ runtimeContext: true })`; they appear as `ai.settings.context.<key>` on the spans.

**Root span shows as LLM instead of AGENT (AI SDK 7).** Your lockfile holds `@arizeai/openinference-vercel` 2.7.x, which only classifies `invoke_agent` as an agent when `gen_ai.agent.name` is present. Pass `telemetry: { functionId }` on the call, or refresh the lockfile to 2.8.1 or newer.

**You want the 6.x span names on AI SDK 7.** Register `LegacyOpenTelemetry` instead of `OpenTelemetry`. It emits the 6.x `ai.generateText` / `ai.generateText.doGenerate` / `ai.toolCall` span names with `ai.usage.*` attributes (TraceRoot still displays the tool span by tool name; one difference from 6.x: it nests under the `doGenerate` span that requested it):

```typescript
import { TraceRoot } from '@traceroot-ai/traceroot';
import { registerTelemetry } from 'ai';
import { LegacyOpenTelemetry } from '@ai-sdk/otel';

TraceRoot.initialize();
registerTelemetry(new LegacyOpenTelemetry());
```
