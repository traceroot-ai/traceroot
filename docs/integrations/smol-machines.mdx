Put the traceroot Agent's sandbox inside a [smol machine](https://smolmachines.com). A smol machine is a microVM, so the code the agent checks out and every command it executes get a kernel separate from the host's. Setting `SANDBOX_PROVIDER=smol` assigns one machine to every agent session, hosted on smol cloud or booted on your own computer.

<Note>
  Only a self-hosted traceroot has this setting. The default provider is `docker`, and it stays in effect until you change `SANDBOX_PROVIDER`. [Self-Hosting](/developer/self-hosting) explains how to run traceroot yourself.
</Note>

## Requirements

- A self-hosted traceroot started through `make dev` or `make prod`, where the agent already has a model provider key.
- smol cloud target: an API key from your smol cloud account. smol machines' [Cloud Quick Start](https://smolmachines.com/docs/cloud) shows where to create it.
- Local target: a Mac with Apple Silicon or a KVM-capable Linux host, started through `make dev`. There is nothing extra to install, because the `smolmachines` package traceroot already depends on includes the local engine.

## Set up

Edit the `.env` file in the repository root and pick a target:

<Tabs>
  <Tab title="smol cloud">
    ```bash
    SANDBOX_PROVIDER=smol
    SMOL_CLOUD_TOKEN=your-api-key
    ```

    smol cloud is used whenever `SMOL_TARGET` is unset. Both `make dev` and `make prod` support it.
  </Tab>
  <Tab title="Local machine">
    ```bash
    SANDBOX_PROVIDER=smol
    SMOL_TARGET=local
    ```

    No smol cloud account is involved: the microVM boots on the host. Supported with `make dev`.
  </Tab>
</Tabs>

Restart traceroot so the agent picks up the change.

## Verify

1. **In the traceroot UI**: start an agent session and have it print the kernel version with `uname -a`. The output describes the microVM's kernel, which is separate from the host's.
2. **In the agent's log**: look for a line that begins with `[SmolExecutor] Machine ready:` and ends with the machine name. For the Docker Compose stack:

   ```bash
   docker compose -f docker-compose.prod.yml logs -f agent
   ```

## What the agent sets up

Machines are created lazily: a session gets one on its first sandbox call.

| Setting | Value |
|---------|-------|
| Base image | `ubuntu:24.04` |
| Tools installed | Git, jq, curl and CA certificates |
| Workspace | `/workspace`, with `repos`, `traces` and `notes` folders |
| Network | Outbound access on, so the agent can clone your repository |
| Idle stop (smol cloud) | After 15 minutes without a command |
| Deletion (smol cloud) | 24 hours after the machine is created |

Repository credentials reach `git` through environment variables and never appear in a command line. Tearing down a session's sandbox, or stopping the agent, removes that session's machine.

## Limitations

- `SMOL_TARGET=local` works under `make dev`. Under `make prod`, the target is always smol cloud.
- The 24-hour deletion counts from creation, so a long session can outlive its machine. Open another session to continue on a fresh one.
- `SANDBOX_IDLE_TTL_MINUTES` and `SANDBOX_RECLAIM_ON_START` are settings for the `docker` provider and have no effect here. The table above gives the timings that apply instead.
- On smol cloud, any command the agent launches without a timeout is stopped at 600 seconds.
- Setup is all or nothing. When a step goes wrong, the half-built machine is removed and the error shows which command failed with what output. A later sandbox call begins again on an empty machine.
