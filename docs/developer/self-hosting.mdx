TraceRoot is open source and supports self-hosting. Run it on your own infrastructure for full control over your data and deployment.

## Deployment Options


### Local Developer Deployment

Best for: contributing to TraceRoot, local development, and debugging.

Starts PostgreSQL, ClickHouse, MinIO, and Redis in Docker, then runs the API, UI, and workers locally via a tmux session.

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
make dev
```

### Local Docker Deployment

Best for: trying TraceRoot locally, integration testing, or running a full stack without local dependencies.

Runs the entire stack in containers using Docker Compose — no need to install Python, Node, or other runtimes locally.

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
cp .env.example .env
# In .env, uncomment SQL_GATEWAY_BOOTSTRAP_PASSWORD and replace its value
# with a unique, strong secret before starting the stack.
make prod
```

See the [README](https://github.com/traceroot-ai/traceroot/blob/main/README.md) for details.


### Production Deployment

Best for: production workloads on AWS.

Choose the deployment repository that matches the infrastructure you already have:

- [TraceRoot Helm chart](https://github.com/traceroot-ai/traceroot-k8s) deploys the application to Kubernetes and connects it to PostgreSQL, ClickHouse, Redis, and S3-compatible storage that you provide.
- [TraceRoot Terraform module for AWS](https://github.com/traceroot-ai/traceroot-terraform-aws) provisions the AWS infrastructure and installs the Helm chart for you.
