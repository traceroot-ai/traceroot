traceroot is open source and supports self-hosting. Run it on your own infrastructure for full control over your data and deployment. Some features require an enterprise license key.

## Deployment Options


### Local Developer Deployment

Best for: contributing to traceroot, local development, and debugging.

Starts PostgreSQL, ClickHouse, MinIO, and Redis in Docker, then runs the API, UI, and workers locally via a tmux session.

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
make dev
```

### Local Docker Deployment

Best for: trying traceroot locally, integration testing, or running a full stack without local dependencies.

Runs the entire stack in containers using Docker Compose — no need to install Python, Node, or other runtimes locally.

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
make prod
```

See the [README](https://github.com/traceroot-ai/traceroot/blob/main/README.md) for details.

### Credentials

`make prod` and `make prod-lite` create a `.env` file and fill in credentials for your install: the database and object store passwords, the auth and internal API secrets, and the key that encrypts stored model provider keys and Slack tokens (`ENCRYPTION_KEY`). Each install gets its own values. To use your own, set them in `.env` before starting; a value copied from `.env.example` is not accepted and the stack stops with a message naming the variable to change.

<Warning>
  Keep a backup of `.env`. If `ENCRYPTION_KEY` is lost, stored model provider keys and Slack tokens can no longer be read and have to be entered again.
</Warning>

The object store API is published on `127.0.0.1` only. Put a reverse proxy in front of it deliberately if you need access from another machine.

### Upgrading an existing install

1. Pull the latest version and run `make prod-lite` (or `make prod`). This replaces any database or object store password in `.env` that was copied from `.env.example` with a generated one.
2. If the stack stops and names `ENCRYPTION_KEY`, your `.env` still has the key from `.env.example`. Run `make rotate-encryption-key` once. It re-encrypts the stored model provider keys and Slack tokens under a new key in a single transaction, writes the new key to `.env`, and saves the previous one in the `.env.encryption-key.d` directory. If it fails before the database is updated, nothing is changed and you can run it again. If the database was updated but `.env` could not be written, the command says so and keeps the new key in `.env.encryption-key.d/pending`; fix the problem and run it again to finish. It refuses to run while `ENCRYPTION_KEY` is set in your shell environment or `COMPOSE_ENV_FILES` is set, because Docker Compose would then not use the key in `.env`. While a rotation is running, or has not finished, the `make` targets that start the stack wait or refuse, so the services never run with a key the database is being moved away from; to start the stack with `docker compose` yourself, finish the rotation first.
3. Start the stack again with `make prod-lite` (or `make prod`). If you started it with `make prod` before, its tmux session is still there and `make prod` offers to re-attach to it; answer `N` so a new session is started. Re-attaching skips the setup and would leave the stopped services stopped.

Rotation stops the web, worker, agent, detector and billing services first. If it fails they stay stopped, and starting is refused until the rotation has finished: fix the problem and run `make rotate-encryption-key` again (to abandon an unfinished rotation that did not change the database, remove `.env.encryption-key.d/pending` and start as in step 3).

An install that never set `ENCRYPTION_KEY` has nothing stored under it and simply gets a generated one.

### Authentication Providers

By default, self-hosted traceroot supports email and password authentication. You can optionally configure social login and AI agent-aided authentication providers in `.env`:

#### Google OAuth (Optional)

To enable Google sign-in:
1. Create OAuth 2.0 credentials in the [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
2. Set the authorized redirect URI to `<BETTER_AUTH_URL>/api/auth/callback/google` (e.g. `http://localhost:3000/api/auth/callback/google`).
3. Add the credentials to `.env`:
   ```bash
   AUTH_GOOGLE_CLIENT_ID=your-google-client-id
   AUTH_GOOGLE_CLIENT_SECRET=your-google-client-secret
   ```

#### AgentID Sign-in for AI Agents (Optional)

traceroot supports agent-aided authentication via [AgentID](https://agentmail.to) (AgentMail's OpenID Connect issuer for autonomous AI agents). This allows AI agents to sign in with their own dedicated agent identity without sharing personal developer Google accounts:
1. Register an OAuth client at [AgentMail](https://agentmail.to).
2. Set the authorized callback URI to:
   ```text
   <BETTER_AUTH_URL>/api/auth/callback/agentid
   ```
3. Add the client credentials to `.env`:
   ```bash
   AUTH_AGENTID_CLIENT_ID=your-agentid-client-id
   AUTH_AGENTID_CLIENT_SECRET=your-agentid-client-secret
   ```

When configured, the **AgentID** sign-in button automatically appears alongside Google on the sign-in and sign-up pages. Agent email addresses are stored with `emailVerified: false` to ensure agent identities remain isolated and cannot merge into existing human accounts.


### Production Deployment

Best for: production workloads on AWS.

Deploy traceroot on Kubernetes using Helm charts and Terraform. Configuration lives in the [`deploy`](https://github.com/traceroot-ai/traceroot/tree/main/deploy) directory.

<Warning>
  Terraform deployment is currently experimental. We recommend testing thoroughly before production use.
</Warning>
