TraceRoot includes a built-in AI agent that serves as both an **investigative trace debugger** and an **interactive project assistant**.

The agent can analyze execution traces, clone production code into sandboxes to locate root causes, and open fix pull requests on GitHub. Beyond investigation, the agent can also modify your project by creating, updating, and deleting monitoring resources—in interactive chat sessions, write actions pause for your explicit confirmation before executing.

## The Home Page & Persistent Chat

The first item in the TraceRoot project sidebar is [Home](/ai-agent/home) (`/projects/{projectId}/home`), a dedicated full-page AI assistant equipped with starter prompts for common tasks:
- *"Investigate the most recent errored trace"*
- *"Summarize today's sessions"*
- *"What did detector findings flag this week?"*

### Conversation Persistence

Chat state is managed by an application-wide provider (`AiChatProvider`), mounted in the root layout:
- **Navigates with you**: A conversation started on the Home page survives navigating across different pages (such as Traces, Dashboards, or Detectors) and remains accessible in the right-hand assistant drawer.
- **Stored sessions**: Conversations are saved as project sessions, allowing you to review past debugging trajectories and findings at any time.
- **Turn-level trace links**: Assistant responses include a **View trace** button when their trace is available or still uploading; failed trace exports are marked unavailable.

## Investigative Capabilities

When debugging issues in your AI applications, the agent provides four core investigation capabilities:

- **Trace analysis** — Ask natural language questions about your traces, error trends, latencies, and token costs without writing manual ClickHouse queries.
- **Root cause analysis (RCA)** — The agent clones your production repository into an isolated sandbox, reads the exact source file and line where an error occurred, and correlates git commit history with trace failures.
- **Automated fix PRs** — After diagnosing a failure, the agent can implement a code fix on a new branch and open a GitHub pull request for human review. The agent never pushes directly to your default branch.
- **Parallel runs** — Launch multiple debugging sessions concurrently to investigate separate traces and failure patterns simultaneously.

## Changing Project Resources (Write Actions)

In addition to querying telemetry via [Agent Tools](/ai-agent/tools), the agent binds **13 write tools** capable of modifying project resources directly through conversation:

| Resource Type | Available Agent Actions | Write Tools |
| :--- | :--- | :--- |
| **Detectors** | Create, configure, or delete LLM-as-a-judge detectors | `create_detector`, `update_detector`, `delete_detector` |
| **Dashboards** | Create, rename, or delete project dashboards | `create_dashboard`, `update_dashboard`, `delete_dashboard` |
| **Widgets** | Add, modify, or remove query charts and trace feeds | `create_widget`, `update_widget`, `delete_widget` |
| **Alerts** | Create, reconfigure, delete, or toggle threshold alerts | `create_alert`, `update_alert`, `delete_alert`, `set_alert_status` |

### Scope Boundary: No Workspace or Project Writes

The agent operates strictly within the project tenancy injected by the active chat session:
- The agent **cannot create, update, or delete workspaces**.
- The agent **cannot create, update, or delete projects**.

Administrative changes to workspaces and projects are intentionally restricted to the CLI, Public REST API, and workspace settings.

## Safety: Interactive Approvals and Timeouts

In interactive user sessions, the agent cannot autonomously modify your project. Every write action is guarded by human confirmation:

### Confirmation Cards

Whenever the agent decides to invoke a write tool during an attended session, execution pauses and presents an interactive **confirmation card** in the chat:
- **Creates and Updates**: You can choose to **Approve** (execute the change), **Skip** (cancel the change), or **Revise** (provide feedback or changes in natural language so the agent re-proposes the action with adjustments).
- **Deletes**: To protect against accidental deletions, destructive actions offer only **Approve** or **Skip**. A skipped deletion is never re-proposed from revisions. Deletes also require an audit justification reason of **3 to 500 characters**.

If you skip or decline an action, the agent acknowledges the skip and continues the conversation without retrying the tool call.

<Note>
  For creates and updates, the confirmation card is a review gate rather than a security control: a request that carries no acting user, such as a system-initiated run, executes them without showing a card. Deletes fail closed instead — with nobody there to approve one, the call is blocked rather than executed.
</Note>

### Background Sessions Get No Write Tools

Unattended background and RCA executions have no human to answer a card, so they are offered no write tools at all — write tools are bound only when the request carries both an acting user and a conversation id. A human follow-up inside an RCA session does carry an acting user, so it is offered them. Should such a session ever reach a write tool, the write policy is the backstop: a delete **fails closed** and is blocked, so the agent can never delete a resource unattended.

### 10-Minute Timeout

In attended sessions, approval cards will not wait indefinitely:
- If an approval proposal is left unanswered for **10 minutes**, TraceRoot automatically skips that pending action.
- No change from the unanswered proposal is applied; earlier approved actions in the same turn remain in effect.
- Only one decision can be pending per chat session at any given time.

## Audit Logging and Agent Traces

Every write the agent executes is recorded in your workspace's append-only audit trail, stamped with `transport: "agent"` and the conversation that authorized it. Internal agent and detector self-traces are tagged `source = "agent"` and `source = "detector"` and are excluded from your Traces and Dashboards pages.

See [Write Actions & Approvals](/ai-agent/write-actions) for what the audit row records, how long it survives, and how agent traces are filtered.
