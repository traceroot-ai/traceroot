An **evaluation** runs your system under test against a dataset of cases and scores each result. In TraceRoot every case runs as its own trace, so you inspect an eval with the same span timeline, token, and cost views you already use for tracing. You author datasets and run evals **for free, offline**, and opt in to reporting when you want the results on the platform.

The SDK is available in **Python** and **TypeScript**, and the two are byte-for-byte identical on identity and output — the same eval reconciles across languages, machines, and processes.

## Concepts

**1. Trace-native.** Each case runs as its own trace: `evaluation-item → task → scorer` spans. An eval *is* a trace you can open and drill into — the model calls your task makes, the tokens they cost, and the scorer's own work are all spans under the case. Nothing new to learn to inspect a run.

**2. Metric-first.** A run has **no single headline score**. Each scorer emits a metric; pass/fail is decided **per score**, from that scorer's declared `threshold` and `direction`. A case's status is `errored` or `not_scored` — never a fabricated "passed". You read a run as *per-metric* means and pass rates, never as one number.

**3. Local-first.** Authoring a dataset and running an eval need no account, no key, and no network. Reporting to the platform is opt-in — it's the default once credentials resolve, and fully suppressible with `local=True` (which exports nothing at all, spans included). Safe to run on a laptop or in CI.

**4. One identity across languages.** A dataset's `dataset_id`, its case ids, its content `revision`, and a scorer or judge's `version` are all **content-hashed** — and identical in Python and TypeScript. Set a stable `key` on a dataset and the same eval converges no matter who runs it, in which language, from which machine.

## What a scorer is

A scorer maps a case's `(input, output, expected, metadata)` to one or more named metrics. There are three escalating forms — a plain function for the happy path, `Scorer.code(...)` when you want a declared pass/fail policy, and `Scorer.llm_judge(...)` when the model and prompt *are* the definition. See [Scorers](/evals/scorers).
