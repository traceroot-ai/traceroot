---
title: Running Evals
description: Run a dataset against your system with evaluate() and score every case
---

`evaluate()` runs your system under test against a dataset, scores every case, and reports the run. Each case runs as its own trace — `evaluation-item → task → scorer` spans — so an eval *is* a trace you can open and drill into.

A run has **no single headline score**. Each scorer emits a metric, and pass/fail is decided per metric by that scorer's declared threshold. A case's status is `errored` or `not_scored` — never a fabricated pass. See [Reading results](/evals/reading-results) for how to read what comes back.

## Signature

<Tabs>
  <Tab title="Python">
    ```python
    from traceroot import evaluate  # also: evaluate_async

    evaluate(
        *,
        name,
        dataset=None,      # a Dataset  — or —
        data=None,         # an inline list of cases
        task,              # your system under test: input -> output
        scorers,           # list of scorers
        local=False,       # run fully; report nowhere
        transport=None,    # explicit reporting sink (mutually exclusive with local)
        candidate_version=None,
        select=None,
        timeout=None,
        evaluation_key=None,
        environment="evaluation",
        progress=None,
        max_concurrency=10,
    ) -> EvalRunResult
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { evaluate } from "@traceroot-ai/traceroot";

    await evaluate({
      name,
      dataset,            // a Dataset  — or —
      data,               // an inline list of cases
      task,               // your system under test: input -> output
      scorers,            // list of scorers
      local,              // run fully; report nowhere
      transport,          // explicit reporting sink (mutually exclusive with local)
      candidateVersion,
      select,
      timeout,
      evaluationKey,
      environment,        // defaults to "evaluation"
      progress,
      maxConcurrency,
      signal,
    }): Promise<EvalRunResult>
    ```
  </Tab>
</Tabs>

<Note>
  Python exposes both `evaluate` and `evaluate_async`. In TypeScript, `evaluate` is already async — always `await` it.
</Note>

## Key parameters

- **`dataset` vs `data`** — supply exactly one. `dataset` is a [`Dataset`](/evals/datasets); `data` is an inline list of cases when you don't want a named, versioned dataset.
- **`task`** — the system under evaluation, an `input -> output` function. It may be async.
- **`scorers`** — a list of any [scorer](/evals/scorers) form (plain function, `Scorer.code`, or `Scorer.llm_judge`).
- **`local=True` / `local: true`** — run in full, but report **nowhere**: no credentials are read, no HTTP is made, no dataset is published, and no spans are exported (a no-op tracer). The ergonomic "just run it." **Mutually exclusive with `transport=`.**
- **`transport=`** — an explicit reporting sink (self-host, custom, or [`FakeTransport`](/evals/transports)). Omit both `local` and `transport` and the run defaults to reporting when a key resolves.
- **`candidate_version` / `candidateVersion`** — labels the thing under test (model id, prompt version, git sha). **This is what the UI groups and compares runs by.**
- **`select`** — run a subset (by id or predicate) without editing the dataset.
- **`timeout`** — bounds each case (task plus its scorers). A timeout is an **isolated per-case error**, not a run failure.
- **`evaluation_key` / `evaluationKey`** — the grouping identity on the wire: how repeated runs of the same eval are grouped server-side.
- **`environment`** — defaults to `"evaluation"`.
- **`progress`** — controls the live progress render. It's on automatically for an interactive TTY; pass `False` / `false` to silence it in scripts and CI.

## Behaviors

**Auto-provision.** A local `Dataset` with no server version is published for you — silently — as the version the run scored. Re-running is silent too: `evaluate()` auto-approves and **never prompts**. The `[y/N]` confirmation applies only to an explicit [`Dataset.push()`](/evals/datasets), never to an eval run.

**It prints itself.** On an interactive terminal (progress shown), `evaluate()` prints `summary()` on completion — no manual print needed. This is gated to interactive terminals; piped, CI, and programmatic stdout stays clean, so it won't corrupt captured output.

## Minimal example

<Tabs>
  <Tab title="Python">
    ```python
    from traceroot import Dataset, evaluate

    ds = Dataset("weather", key="weather")
    ds.add({"city": "SF"}, expected="68°F")

    def task(input):        # your system under test
        return look_up_weather(input["city"])

    def reports_temp(input, output, expected=None):
        return expected in (output or "")

    result = evaluate(
        name="weather",
        dataset=ds,
        task=task,
        scorers=[reports_temp],
        candidate_version="weather-v1",
        local=True,          # run fully offline; report nowhere
    )
    # summary() auto-prints on a TTY; result is also returned for programmatic use
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { Dataset, evaluate } from "@traceroot-ai/traceroot";

    const ds = new Dataset("weather", null, { key: "weather" });
    ds.add({ city: "SF" }, { expected: "68°F" });

    async function task(input) {           // your system under test
      return lookUpWeather(input.city);
    }

    function reportsTemp({ input, output, expected }) {
      return (output ?? "").includes(expected);
    }

    const result = await evaluate({
      name: "weather",
      dataset: ds,
      task,
      scorers: [reportsTemp],
      candidateVersion: "weather-v1",
      local: true,           // run fully offline; report nowhere
    });
    // summary() auto-prints on a TTY; result is also returned for programmatic use
    ```
  </Tab>
</Tabs>

<Note>
  `local=True` truly leaks nothing — no spans are exported — so it's safe on a laptop or in CI without a key. Reporting to the platform is the default only when credentials resolve and neither `local` nor `transport` overrides it.
</Note>
