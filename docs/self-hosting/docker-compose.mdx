---
title: Docker Compose Deployment
description: Deploy a standalone production TraceRoot stack using Docker Compose
---

Docker Compose is the fastest way to run TraceRoot on a single virtual machine, bare metal server, or local environment. The stack includes all six application services, background workers, databases, and automatic migration runners.

## Prerequisites

You need Docker Engine 24.0+ with Docker Compose v2.20+. The minimum host is 4 vCPUs, 8 GB RAM, and 30 GB of SSD storage; for production, use 8 vCPUs, 16+ GB RAM, and 100+ GB of NVMe storage.

## Step-by-step installation

### 1. Clone the repository

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
```

### 2. Create the environment file

Copy `.env.example` to `.env`:

```bash
cp .env.example .env
```

`.env.example` comes with `ENABLE_BILLING=false` pre-configured. This unlocks all features, disables cloud rate limiting, and bypasses seat restrictions.

### 3. Generate required secrets

`docker-compose.prod.yml` enforces three mandatory secrets. If any of these are empty or missing, Docker Compose will refuse to start:

- `BETTER_AUTH_SECRET`
- `INTERNAL_API_SECRET`
- `SQL_GATEWAY_BOOTSTRAP_PASSWORD`

You can populate these in `.env` automatically using `openssl`:

```bash
# On Linux / macOS:
for key in BETTER_AUTH_SECRET INTERNAL_API_SECRET SQL_GATEWAY_BOOTSTRAP_PASSWORD; do
  sed -i.bak -E "s|^#? *${key}=.*|${key}=$(openssl rand -hex 32)|" .env
done
rm -f .env.bak
```

`SQL_GATEWAY_BOOTSTRAP_PASSWORD` ships commented out, so the pattern allows a leading `#` and keeps working once that line is uncommented.

Or generate each secret manually using `openssl` and paste unique values into your `.env`:

```bash
# Run this command to generate distinct 32-byte hex strings:
openssl rand -hex 32
```

In `.env`:
```bash .env
BETTER_AUTH_SECRET=<unique-32-byte-hex-from-openssl>
INTERNAL_API_SECRET=<unique-32-byte-hex-from-openssl>
SQL_GATEWAY_BOOTSTRAP_PASSWORD=<unique-32-byte-hex-from-openssl>
```

### 4. Optional: configure AI provider keys

If you plan to use the AI Agent or automated LLM-as-a-judge detectors, add your API keys to `.env`:

```bash .env
ANTHROPIC_API_KEY=sk-ant-api03-...
OPENAI_API_KEY=sk-proj-...
```

## Starting the stack

Run Docker Compose to build images and launch all services in detached mode:

```bash
docker compose -f docker-compose.prod.yml up --build -d
```

Alternatively, you can use the make target:

```bash
make prod-lite
```

`make prod-lite` is not the same command: it runs `up --build` attached, so the stack stops when you press Ctrl+C, and it copies `.env.example` to `.env` first if no `.env` exists. Run it before step 3 and `SQL_GATEWAY_BOOTSTRAP_PASSWORD` is still commented out in the generated file, so Compose refuses to start.

`make prod` launches a live terminal tmux dashboard that requires local `uv` and Python installations. For a detached container-only deployment, use `docker compose -f docker-compose.prod.yml up --build -d`.

## Verifying the deployment

Inspect the status of all containers:

```bash
docker compose -f docker-compose.prod.yml ps
```

The databases (`postgres`, `clickhouse`, `redis`, `minio`) report `Up (healthy)`, the migration services (`migrate`, `clickhouse-init`, `migrate-clickhouse`) report `Exited (0)`, and the application services (`web`, `rest`, `worker`, `billing`, `detector`, `agent`) report `Up`:


## Service endpoints

Once running, access the services on your host machine:

| Endpoint | URL | Notes |
| :--- | :--- | :--- |
| **Web Console** | `http://localhost:3000` | Sign up / log in to access your dashboard |
| **REST API** | `http://localhost:8000` | Ingestion, healthchecks, and public endpoints |
| **MinIO Console** | `http://localhost:9091` | Default credentials: `minio` / `minio-password` (local only; change for production) |

## Stopping and updating

### Stop the stack

```bash
docker compose -f docker-compose.prod.yml down
```

### Stop and wipe all data volumes

<Warning>
This command deletes all persistent database data (PostgreSQL, ClickHouse, Redis, and MinIO storage).
</Warning>

```bash
docker compose -f docker-compose.prod.yml down -v
```

### Updating to the latest version

```bash
git pull origin main
docker compose -f docker-compose.prod.yml up --build -d
```
Automatic migrations will run first before updating the application services.
