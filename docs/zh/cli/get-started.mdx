traceroot CLI 用一条命令在你的仓库里设置好追踪，之后你可以在终端里操作项目：trace、detector finding、告警、仪表盘、评测和 SQL。输出的 JSON 可以通过管道交给下一步处理。它是为 AI coding agent 和偏好命令行的重度用户设计的。

源码在 [`traceroot-cli`](https://github.com/traceroot-ai/traceroot-cli) 仓库里。

## 设置一个仓库

在你想要追踪的仓库根目录下运行：

```bash
npx -y traceroot-cli@latest setup
```

setup 会让你登录，让你的 coding agent 添加 traceroot SDK，然后等待第一条 trace 到达。你不需要事先安装或登录。[追踪](/zh/tracing/get-started)页面讲解了每个步骤、自托管和问题排查。

### 无提示运行

在以下情况下 setup 不会弹出任何提示：没有连接到终端；`CI` 的值既不为空也不是 `false`；或者传了 `--no-input` 或 `--json`。这时请把它原本会问的内容直接传进去：

```bash
npx -y traceroot-cli@latest setup --no-input --api-key "$TRACEROOT_API_KEY"
```

项目 API key 同时也确定了项目。没有 key 时，先运行 `npx -y traceroot-cli@latest login`，再运行不带 `--api-key` 的 setup。login 会打印一个 URL 和一个验证码，等待有人在浏览器里确认，所以 coding agent 必须把它们展示给你。如果 setup 以退出码 10 退出，说明它没法替你做选择，通常是因为你有多个项目或一个项目都没有：按它打印的解决办法操作即可。有多个项目时，可以传 `--project`。

无提示运行时，setup 遇到未提交的改动只会给出提示，不再询问；它也不会运行 coding agent，只把插桩任务写到 `.traceroot/prompts/setup-instrument.md`。要运行 coding agent，请传 `--agent claude` 或 `--agent codex`。任务完成、应用也运行过之后，带上 `--resume` 重新运行同一条 setup 命令，例如 `npx -y traceroot-cli@latest setup --no-input --resume`，就能拿到第一条 trace 的链接。[退出码](/zh/cli/scripting#退出码)列出了每个退出码的含义，[Coding agents](/zh/getting-started/coding-agents#设置追踪) 页面把这些步骤写成了一段提示词。

### setup 的 flag

| Flag | 含义 |
| :- | :- |
| `--agent <agent>` | 要运行的 coding agent：`claude` 或 `codex`。其他 agent 请用 `--no-instrument` |
| `--language <language>` | 要插桩的语言：`python` 或 `typescript` |
| `--service <path>` | monorepo 里要插桩的服务 |
| `--project <name-or-id>` | 接收 trace 的项目 |
| `--no-browser` | 粘贴 API key 登录，不使用浏览器 |
| `--no-instrument` | 只写出插桩任务，不运行 agent |
| `--manual` | 只打印操作说明，不运行 agent，也不写任务 |
| `--resume` | 从保存的检查点继续 |
| `--no-input` | 永不提示。缺少答案时会退出，并告诉你该传哪个 flag |
| `--trace-timeout <seconds>` | 等待第一条 trace 的时长。默认：120 |

## 安装

每条命令都可以像上面那样通过 `npx` 运行。想保留 `traceroot` 这个命令，就全局安装 CLI：

```bash
npm install -g traceroot-cli
```

下面的示例都使用 `traceroot`。没有全局安装时，把它换成 `npx -y traceroot-cli@latest`。

CLI 需要 Node.js 20.3 或更高版本，`setup` 需要 20.12 或更高版本。`traceroot --version` 会打印你当前的版本。

## 认证

CLI 有两种认证方式：**浏览器登录**（默认的交互式设备流程）和**项目 API key**（用于 CI 环境和脚本）。

### 浏览器登录（默认）

运行 `traceroot login`，通过浏览器登录：

```bash
traceroot login
```

它会打印一个 URL 和一个验证码，尝试打开你的浏览器，并把会话保存到 `~/.config/traceroot/credentials.json`。如果浏览器没有打开，请自己打开这个 URL。已有的 key 或已保存的凭证会[改变 `login` 的行为](/zh/cli/authentication#login-做了什么)。

### API key 登录（CI 与脚本）

在 CI 流水线、自动化脚本或没有图形界面的环境里，使用项目 API key（`tr-...`）：

```bash
traceroot login --api-key tr-...
```

这条命令会向 API 验证这个 key，并把它保存到 `./.traceroot/config.json`。

你也可以设置 `TRACEROOT_API_KEY`，不过已保存的浏览器登录[优先级比它高](/zh/cli/authentication#使用哪个凭证)。项目 API key [不能创建或修改资源](/zh/cli/authentication#浏览器登录与-api-key)。

在 [traceroot Cloud](https://app.traceroot.ai) 或你的[自托管](/zh/developer/self-hosting)部署里创建 API key。

### 验证凭证

确认当前生效的身份：

```bash
traceroot status
```

- **浏览器登录**：显示你已认证的邮箱地址、host URL、当前项目（或者提示你选一个），以及你能访问的工作空间。
- **API key 登录**：显示你的工作空间、项目、host URL，以及打了码的 key 提示（例如 `tr-d0a3-57e3`）。

## 限定到某个项目

浏览器登录代表的是你本人，覆盖你所有的工作空间，不绑定到某一个项目。而 `traces`、`evals` 这类命令是项目级的，所以要先选一个项目。API key 本身已经限定在它所属的项目里，用 key 登录可以跳过这一步。

列出你能访问的项目，找到项目 ID：

```bash
traceroot projects list
```

设置 `TRACEROOT_PROJECT_ID`，后面的命令就不用再加 flag；也可以给单条命令传 `--project <id>`：

```bash
export TRACEROOT_PROJECT_ID=<project-id>
```

完整的优先级顺序见[选择项目](/zh/cli/authentication#选择项目)。

## 查看和导出 trace

认证并限定到某个项目之后，就可以列出、查看和导出 trace：

```bash
# 最近的 trace
traceroot traces list --limit 10

# 以 JSON 输出一条 trace，包含 span 的输入输出
traceroot traces get <trace-id> --fields full --json

# 把一条 trace 打包保存到本地
traceroot traces export <trace-id> --output ./my-trace
```

[Traces](/zh/cli/traces) 页面讲解了时间筛选、字段组和导出的文件。

## 诊断与添加 skill

```bash
traceroot doctor
traceroot setup doctor --service ./api
traceroot instrument --agent claude --print
traceroot skills install traceroot-instrument-repo --agent claude --dry-run
```

`doctor` 会检查凭证、traceroot 文件、仓库、环境和已安装的 skill。`setup doctor` 用来诊断没有完成的 setup。在 monorepo 里两者都接受 `--service <path>`，有检查项失败时以退出码 1 退出。

`instrument` 会写出一段提示词，让 coding agent 添加 traceroot，它本身不改你的代码。它接受 `--agent`（`claude`、`codex` 或 `generic`）、把提示词写到 stdout 的 `--print`、`--output <path>`，以及覆盖已有提示词的 `--force`。通常直接用 `setup` 就行。

`skills list` 显示 CLI 自带的 skill 以及它们的安装位置。`skills install` 把其中一个复制到某个 agent 的 skill 目录，接受 `--agent`、`--force`，以及只展示将要写入内容的 `--dry-run`。[Coding agents](/zh/getting-started/coding-agents#skills) 页面列出了可以使用的 skill。

## 命令参考

给任意命令加上 `--json` 可以得到机器可读的输出，运行 `traceroot <command> --help` 可以查看完整的 flag 列表。

`sql` 命令的文档在[只读 SQL](/zh/cli/sql) 页面。

| Command | Description |
| :--- | :--- |
| `setup` | Connect this repository to traceroot and see your first trace. See [Tracing](/zh/tracing/get-started). |
| `setup doctor` | Diagnose a setup that did not complete. Flag: `--service <path>`. |
| `login` | Sign in with the browser (device flow), or persist an explicit --api-key. |
| `logout` | Revoke the session server-side (best-effort) and remove the local credential. |
| `status` | Show the identity your credentials resolve to (email or key hint, workspace, project, and host). |
| `doctor` | Check local environment, credentials, configuration, repository, and agent skills. |
| `instrument` | Generate an agent prompt to instrument this repo with traceroot. |
| `skills list` | List available AI agent skills and their capabilities. |
| `skills install` | Install skills into your coding agent workspace. |
| `traces list` | List recent traces for the caller's project (newest first). |
| `traces get <id>` | Get a single trace for the caller's project. |
| `traces export <id>` | Export the trace bundle (trace + spans + git_context + manifest) for the caller's project. |
| `detectors list` | List the detectors in the caller's project (newest first). |
| `detectors get <id>` | Get one detector's full configuration for the key's project. |
| `findings list` | List recent detector findings for the caller's project (newest first). |
| `findings get <finding-id>` | Get a single finding by id for the key's project. |
| `alerts list` | List the alerts in the caller's project (oldest first) with its capacity. |
| `alerts get <id>` | Get one alert with its full rule for the caller's project. |
| `alerts create` | Create a threshold alert in a project the authenticated user can write to. |
| `alerts update <id>` | Edit an alert's rule in a project the authenticated user can write to. |
| `alerts status <id>` | Pause or resume an alert without touching its rule. |
| `alerts delete <id>` | Hard-delete an alert. |
| `dashboards list` | List the dashboards in the caller's project (default first). |
| `dashboards get <id>` | Get one dashboard with its widgets for the caller's project. |
| `dashboards create` | Create a dashboard in a project the authenticated user can write to. |
| `dashboards update <id>` | Edit a dashboard's name or description. |
| `dashboards delete <id>` | Hard-delete a dashboard together with its widgets. |
| `workspaces list` | List the workspaces the authenticated user belongs to. |
| `projects list` | List the projects the authenticated user can access, across workspaces. |
| `workspaces create` | Create a workspace administered by the authenticated user. |
| `workspaces update <workspace-id>` | Rename a workspace the authenticated user administers. |
| `workspaces delete <workspace-id>` | Hard-delete a workspace and everything in it. |
| `projects create` | Create a project in a workspace the authenticated user can write to. |
| `projects update <project-id>` | Edit a project's name or trace retention. |
| `projects delete <project-id>` | Soft-delete a project. |
| `detectors create` | Create a detector in a project the authenticated user can write to. |
| `detectors update <id>` | Edit a detector in a project the authenticated user can write to. |
| `detectors delete <id>` | Hard-delete a detector; its existing findings stay readable. |
| `widgets get <id>` | Get one saved widget's definition, with its dashboard, for the caller's project. |
| `widgets data <id>` | Answer one saved widget for a window, with a status instead of an exception. |
| `widgets create` | Create a widget on a dashboard the authenticated user can write to. |
| `widgets update <id>` | Edit a widget's title, spec, or display config. |
| `widgets delete <id>` | Hard-delete a widget and its entry in the dashboard's layout. |
| `sql` | Run one read-only SQL query scoped to the caller's project. |
| `sql schema` | Return the curated tables and columns available to public SQL. |
| `datasets list` | List datasets, newest first. |
| `datasets get <dataset-id>` | Read one dataset. |
| `datasets versions list <dataset-id>` | List versions newest-first, each with its case count and whether it is current. |
| `datasets versions get <version-id>` | Read an immutable snapshot: the version plus its cases, whole or a page at a time. |
| `evals list` | List evaluations, newest first, each with its run count and latest run. |
| `evals runs list` | List evaluation runs, newest first, optionally one evaluation's or one status's. |
| `evals runs get <id>` | Read a run's own summary: status, result counts, and per-score and per-metric means over the run's results. |
