<Note>

</Note>

traceroot 是开源的，支持自托管。在自己的基础设施上运行它，可以完全掌控数据和部署。部分功能需要企业版 license key。

## 部署方式


### 本地开发部署

适用于：为 traceroot 贡献代码、本地开发和调试。

在 Docker 里启动 PostgreSQL、ClickHouse、MinIO 和 Redis，然后通过一个 tmux 会话在本地运行 API、UI 和 worker。

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
make dev
```

### 本地 Docker 部署

适用于：在本地试用 traceroot、做集成测试，或者不想在本地安装依赖就运行完整的服务。

用 Docker Compose 在容器里运行整套服务，不需要在本地安装 Python、Node 或其他运行时。

```bash
git clone https://github.com/traceroot-ai/traceroot.git
cd traceroot
make prod
```

详情请看 [README](https://github.com/traceroot-ai/traceroot/blob/main/README.md)。

### 凭证

`make prod` 和 `make prod-lite` 会创建一个 `.env` 文件，并为你的安装填好凭证：ClickHouse、SQL gateway 和对象存储的密码、认证密钥和内部 API 密钥，以及用来加密已保存的模型提供商 key 和 Slack token 的密钥（`ENCRYPTION_KEY`）。每次安装都会得到各自不同的值。PostgreSQL 是例外：除非你在 `.env` 里设置了 `POSTGRES_PASSWORD`，它会一直使用默认密码 `postgres`。如果想用自己的值，请在启动之前写入 `.env`。从 `.env.example` 复制过来的值不会被接受，服务会停止启动，并提示需要修改哪个变量。

<Warning>
  请备份 `.env`。如果 `ENCRYPTION_KEY` 丢失，已保存的模型提供商 key 和 Slack token 将无法读取，只能重新填写。
</Warning>

对象存储的 API 只发布在 `127.0.0.1` 上。如果确实需要从其他机器访问，请自行在它前面加一层反向代理。

### 升级已有的安装

1. 拉取最新版本并运行 `make prod-lite`（或 `make prod`）。如果 `.env` 里的 ClickHouse、SQL gateway 或对象存储密码是从 `.env.example` 复制来的，这一步会把它们替换成自动生成的密码。
2. 如果服务停止启动并提到 `ENCRYPTION_KEY`，说明你的 `.env` 里还是 `.env.example` 里的那个 key。运行一次 `make rotate-encryption-key`。它会在一个事务里用新 key 重新加密已保存的模型提供商 key 和 Slack token，把新 key 写入 `.env`，并把旧 key 保存在 `.env.encryption-key.d` 目录里。如果它在数据库更新之前失败，不会有任何改动，你可以重新运行。如果数据库已经更新但 `.env` 无法写入，命令会给出提示，并把新 key 保留在 `.env.encryption-key.d/pending` 里。解决问题后再运行一次即可完成。如果你的 shell 环境里设置了 `ENCRYPTION_KEY`，或者 `COMPOSE_ENV_FILES` 指向了 `.env` 以外的文件，它会拒绝运行，因为这种情况下 Docker Compose 不会使用 `.env` 里的 key。在轮换进行中或尚未完成时，用来启动服务的 `make` 目标会等待或拒绝执行，这样各个服务就不会用数据库正在弃用的 key 运行。如果想自己用 `docker compose` 启动服务，请先完成轮换。
3. 再次用 `make prod-lite`（或 `make prod`）启动服务。如果之前是用 `make prod` 启动的，它的 tmux 会话还在，`make prod` 会询问是否重新连接。请回答 `N`，让它启动一个新的会话。重新连接会跳过设置步骤，已停止的服务会一直保持停止。

轮换会先停止 web、worker、agent、detector 和 billing 服务。如果轮换失败，这些服务会保持停止，在轮换完成之前无法启动：请解决问题后再次运行 `make rotate-encryption-key`（如果要放弃一次没有改动数据库的未完成轮换，请删除 `.env.encryption-key.d/pending`，然后按第 3 步启动）。

从未设置过 `ENCRYPTION_KEY` 的安装没有用它加密保存的内容，会直接得到一个自动生成的 key。


### 生产部署

适用于：生产工作负载。

traceroot 运行在 Kubernetes 上。部署相关的内容放在两个独立的、带版本的仓库里，你可以固定某个发布版本，按自己的节奏升级。

| 仓库 | 提供什么 |
|---|---|
| [traceroot-terraform-aws](https://github.com/traceroot-ai/traceroot-terraform-aws) | 一个 Terraform 模块，在 AWS 上创建整套环境：VPC、EKS、RDS（PostgreSQL）、ElastiCache（Redis）、ECR、S3、EFS、ACM 和 ALB ingress，然后替你安装 Helm chart。 |
| [traceroot-k8s](https://github.com/traceroot-ai/traceroot-k8s) | 适用于任何 Kubernetes 集群的 Helm chart。如果基础设施由你自己管理，可以直接用它运行 traceroot。 |

**在 AWS 上**，使用 Terraform 模块。这是搭建生产部署最快的方式：

```hcl
module "traceroot" {
  source = "github.com/traceroot-ai/traceroot-terraform-aws?ref=<release-tag>"

  environment = "production"
  name        = "traceroot-production"
  aws_region  = "us-east-1"
  vpc_cidr    = "10.0.0.0/16"
  domain      = "traceroot.example.com"
  image_tag   = "<image-tag>"
}
```

所有输入参数请看[模块的 README](https://github.com/traceroot-ai/traceroot-terraform-aws#readme)，可以直接运行的示例在 [`examples/quickstart`](https://github.com/traceroot-ai/traceroot-terraform-aws/tree/main/examples/quickstart)。

**在其他 Kubernetes 集群上**，用 Helm 安装 chart：

```bash
helm repo add traceroot https://traceroot-ai.github.io/traceroot-k8s
helm repo update
helm install traceroot traceroot/traceroot -f my-values.yaml
```

配置方法请看 [chart 的 README](https://github.com/traceroot-ai/traceroot-k8s#readme) 和它的 [`values.yaml`](https://github.com/traceroot-ai/traceroot-k8s/blob/main/charts/traceroot/values.yaml)。

<Tip>
  请把模块的 `ref` 和 chart 的版本固定到某个发布版本，不要跟随 `main`。
</Tip>
