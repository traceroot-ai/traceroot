用 [traceroot Codex 插件](https://github.com/traceroot-ai/traceroot-codex-plugin)实时追踪 Codex 的每一轮，包括模型调用、工具调用、子 agent 和 token 用量。

## 安装

需要 Node.js 22 或更高版本。

```bash
codex plugin marketplace add traceroot-ai/traceroot-codex-plugin
codex plugin add tracing@traceroot-codex-plugin
codex features enable hooks
```

启动 `codex`，在 “Hooks need review” 提示处选择 **Trust all and continue**，也可以之后用 `/hooks` 信任这些 hook。

## 设置

创建 `~/.codex/traceroot.json`：

```json
{
  "enabled": true,
  "api_key": "your-key-from-app.traceroot.ai"
}
```

插件以 Codex hook 的方式运行，hook 不一定能继承你的 shell 环境，所以推荐使用配置文件。

| 设置项 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | `TRACE_TO_TRACEROOT` | `false` | 开启追踪。还必须设置 API key。 |
| `api_key` | `TRACEROOT_CODEX_API_KEY` 或 `TRACEROOT_API_KEY` | — | 必填。 |
| `host_url` | `TRACEROOT_CODEX_HOST_URL` 或 `TRACEROOT_HOST_URL` | `https://app.traceroot.ai` | 仅在自托管时设置。 |
| `user_id` | `TRACEROOT_CODEX_USER_ID` | — | 记录在每条 trace 上。 |
| `capture_images` | `TRACEROOT_CODEX_CAPTURE_IMAGES` | `false` | 发送工具输出里的截图和提示词附带的图片。 |
| `debug` | `TRACEROOT_CODEX_DEBUG` | `false` | 把诊断信息输出到 stderr。 |

环境变量的优先级高于项目里的 `.codex/traceroot.json`，后者又高于全局文件。`api_key`、`host_url` 和 `capture_images` 只从环境变量或全局文件读取，所以你打开的仓库无法把你的 trace 改发到别处。[插件 README](https://github.com/traceroot-ai/traceroot-codex-plugin#configure) 列出了所有设置。

## 使用

照常使用 Codex。每一轮都会成为一条 trace，在 Codex 工作时实时发送。同一个线程的 trace 共用一个会话 ID。

```
Codex Turn                   # AGENT span：每一轮一个
├── gpt-…                    # LLM span：token，包含推理 token
│   ├── exec_command         # TOOL span：命令、退出码、输出
│   ├── exec
│   └── spawn_agent          # TOOL span：子 agent 的一轮
```

对于 `codex exec` 和其他不会弹出提示的运行，需要先完成信任，因为未被信任的 hook 会被直接跳过，没有任何消息。运行 `codex exec --skip-git-repo-check "echo hello" < /dev/null`，输出里应该包含 `hook: Stop Completed`。[README](https://github.com/traceroot-ai/traceroot-codex-plugin#headless-runs) 说明了如何把信任带到 CI 里。

## 验证

在 Codex 里运行一个提示词，确认 trace 已经到达：
1. **在 traceroot 界面中**：进入 [traceroot Cloud](https://app.traceroot.ai) 的 **Tracing > Traces**。你会看到一条根 span 为 `Codex Turn` 的 trace。
2. **通过 CLI**：运行 `traceroot traces list`，在终端里查看最近的 trace。

## 采集的内容

| 属性 | 说明 |
|---|---|
| 轮次 | 每一轮一条 trace，按 Codex 线程分组 |
| 模型调用 | model ID、提示词和响应 |
| Token | 输入、输出和推理的 token 数量 |
| 工具调用 | 工具名称、输入、输出、状态和退出码 |
| 子 agent | 子 agent 的各个轮次，挂在启动它的工具 span 下 |
| 图片 | 截图和提示词里的图片，需要开启 `capture_images` |
| 用户、环境、git | `user_id`、`environment`、仓库和 commit |

提示词、工具输入和工具输出都会原样发送，包括命令和文件内容，不做任何脱敏。自托管实例在 `ATTACHMENT_ENABLED=true` 时会把图片存为附件。详见[数据采集与隐私](/zh/tracing/data-capture#默认采集的内容)。

## 限制

- 如果没有收到 trace，请确认 hook 已被信任（`/hooks`），并且 `enabled` 为 `true`。把 `debug` 设为 `true`（`TRACEROOT_CODEX_DEBUG`）可以把日志输出到 stderr。
- 每次插件更新之后，Codex 都会让你重新信任这些 hook。在你信任之前，不会发送任何 trace。
