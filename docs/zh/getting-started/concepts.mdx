## 工作空间和项目

一个工作空间包含你的团队和团队的所有项目。成员身份和角色都属于工作空间，你的角色对其中所有项目生效。工作空间设置里包括成员管理，以及 Slack、模型提供商等集成。

一个项目汇集了某个应用的 trace、detector、eval、数据集、仪表盘和告警。打开产品页面之前，先选好要使用的工作空间和项目。

项目 API key 只对一个项目有效。在项目的设置里创建 key，然后在需要向该项目发送数据的应用里配合 SDK 使用。一个项目的 key 无法访问其他项目的数据。请妥善保管 key，不要泄露。

## 环境

环境用来标记项目内的流量，例如 `production` 或 `staging`。它只是 trace 数据上的一个字段，不构成单独的工作空间、项目或权限边界。用环境筛选条件可以只看某一个部署。

部署标签保存在 span 的 `traceroot.environment` 属性里。使用 [TypeScript SDK](/zh/tracing/typescript-sdk) 时，设置 `TRACEROOT_ENVIRONMENT` 即可标记部署。

## 邀请团队成员

1. 以工作空间 ADMIN 的身份打开工作空间的 **Settings**，选择 **Members**。
2. 点击 **Invite member**，输入对方的邮箱地址，并选择 VIEWER、MEMBER 或 ADMIN。
3. 发送邀请。对方会收到一封邮件，里面有邀请页面的链接。
4. 对方打开链接，用受邀的邮箱地址登录，即可接受邀请。

管理员可以在 Members 标签页管理待处理的邀请，并修改成员的角色。发送和接受邀请都受工作空间席位上限的限制。如果接受邀请时提示工作空间已满，请让管理员腾出一个席位或更换套餐。

## 角色

角色从低到高依次是 VIEWER、MEMBER、ADMIN。较高的角色拥有较低角色的全部权限。下表针对已登录的工作空间成员，项目 API key 有自己的凭证权限范围。

| 操作 | VIEWER | MEMBER | ADMIN |
| :-- | :--: | :--: | :--: |
| 查看项目的 trace、detector、仪表盘和告警 | 是 | 是 | 是 |
| 创建和编辑 detector | 否 | 是 | 是 |
| 创建和编辑仪表盘及组件 | 否 | 是 | 是 |
| 创建、编辑、暂停和恢复告警 | 否 | 是 | 是 |
| 创建项目 | 否 | 是 | 是 |
| 创建和编辑项目 API key | 否 | 是 | 是 |
| 删除项目 API key | 否 | 否 | 是 |
| 邀请成员、修改角色或移除成员 | 否 | 否 | 是 |
| 重命名项目或修改其数据保留设置 | 否 | 否 | 是 |
| 删除项目 | 否 | 否 | 是 |
| 重命名或删除工作空间 | 否 | 否 | 是 |

如果通过 API 或 CLI 写入时返回权限错误，请检查你在该项目所属工作空间中的角色。在一个工作空间里是 MEMBER，并不代表你在另一个工作空间里是 ADMIN。可以请工作空间管理员代为操作，或者调整你的角色。
