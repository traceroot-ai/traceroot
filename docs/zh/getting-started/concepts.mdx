## Workspace 和 project

一个 workspace 包含你的团队和团队的所有 project。成员身份和角色都属于 workspace，你的角色对其中所有 project 生效。workspace 设置里包括成员管理，以及 Slack、模型提供商等集成。

一个 project 汇集了某个应用的 trace、detector、eval、dataset、dashboard 和 alert。打开产品页面之前，先选好要使用的 workspace 和 project。

project API key 只对一个 project 有效。在 project 的设置里创建 key，然后在需要向该 project 发送数据的应用里配合 SDK 使用。一个 project 的 key 无法访问其他 project 的数据。请妥善保管 key，不要泄露。

## 环境

环境用来标记 project 内的流量，例如 `production` 或 `staging`。它只是 trace 数据上的一个字段，不构成单独的 workspace、project 或权限边界。用环境筛选条件可以只看某一个部署。

部署标签保存在 span 的 `traceroot.environment` 属性里。使用 [TypeScript SDK](/zh/tracing/typescript-sdk) 时，设置 `TRACEROOT_ENVIRONMENT` 即可标记部署。

## 邀请团队成员

1. 以 workspace ADMIN 的身份打开 workspace 的 **Settings**，选择 **Members**。
2. 点击 **Invite member**，输入对方的邮箱地址，并选择 VIEWER、MEMBER 或 ADMIN。
3. 发送邀请。对方会收到一封邮件，里面有邀请页面的链接。
4. 对方打开链接，用受邀的邮箱地址登录，即可接受邀请。

管理员可以在 Members 标签页管理待处理的邀请，并修改成员的角色。发送和接受邀请都受 workspace 席位上限的限制。如果接受邀请时提示 workspace 已满，请让管理员腾出一个席位或更换套餐。

## 角色

角色从低到高依次是 VIEWER、MEMBER、ADMIN。较高的角色拥有较低角色的全部权限。下表针对已登录的 workspace 成员，project API key 有自己的凭证权限范围。

| 操作 | VIEWER | MEMBER | ADMIN |
| :-- | :--: | :--: | :--: |
| 查看 project 的 trace、detector、dashboard 和 alert | 是 | 是 | 是 |
| 创建和编辑 detector | 否 | 是 | 是 |
| 创建和编辑 dashboard 及组件 | 否 | 是 | 是 |
| 创建、编辑、暂停和恢复 alert | 否 | 是 | 是 |
| 创建 project | 否 | 是 | 是 |
| 创建和编辑 project API key | 否 | 是 | 是 |
| 删除 project API key | 否 | 否 | 是 |
| 邀请成员、修改角色或移除成员 | 否 | 否 | 是 |
| 重命名 project 或修改其数据保留设置 | 否 | 否 | 是 |
| 删除 project | 否 | 否 | 是 |
| 重命名或删除 workspace | 否 | 否 | 是 |

如果通过 API 或 CLI 写入时返回权限错误，请检查你在该 project 所属 workspace 中的角色。在一个 workspace 里是 MEMBER，并不代表你在另一个 workspace 里是 ADMIN。可以请 workspace 管理员代为操作，或者调整你的角色。
