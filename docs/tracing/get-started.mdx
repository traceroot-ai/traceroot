Run this from the root of the repository you want to trace:

```bash
npx -y traceroot-cli@latest setup
```

Setup signs you in, has your coding agent add the TraceRoot SDK, and waits for your first trace. It needs Node.js 20.12 or later and a Python or TypeScript/JavaScript application. Prefer to add the SDK yourself? Skip to [Set up manually](#set-up-manually).

## What setup does

1. Checks for uncommitted changes, since your coding agent's edits would be mixed in with them. If there are any, it asks before continuing; without prompts, it notes them and continues.
2. Signs you in through your browser, where you can also create a free account.
3. Picks one of your projects, or creates one.
4. Writes a project API key as `TRACEROOT_API_KEY` to your application's `.env.local` or `.env`, and refuses an env file that git tracks. The key can send traces and read this project, but not manage its keys.
5. Adds tracing the way you choose: it runs Claude Code or Codex to make the change, writes the task for another coding agent, or prints the steps.
6. Waits for your first trace and prints a link to it. If setup wrote the task or printed the steps, it checks once and pauses instead. After tracing is added and your application has run, `npx -y traceroot-cli@latest setup --resume` looks again.

Setup asks only what it can't work out itself. In a monorepo, run it from the service's directory or pass `--service <path>`. For every option, run `npx -y traceroot-cli@latest setup --help`.

Besides the env file and your code, setup keeps a checkpoint and a report of the run in `.traceroot/`, which it git-ignores, and installs the TraceRoot skill for your coding agent. When you sign in through the browser, `.traceroot/config.json` also holds an admin key the CLI uses for itself. If a run is cancelled or fails, it revokes the keys it created and restores your env file. If it pauses because no trace has arrived or the agent could not finish, it keeps the key so `--resume` can pick up where it stopped. It never reverts your coding agent's edits, so review them with `git diff`.

This configures only the machine you ran it on. Your deployed application needs `TRACEROOT_API_KEY` in its own environment too, plus `TRACEROOT_HOST_URL`, set to your API's origin (the value you pass setup as `--host`), if you self-host.

## Self-hosted TraceRoot

Point setup at your deployment with `--host`, your API's origin, and `--auth-host`, your web app's origin, where browser sign-in happens. For a local deployment with the default ports:

```bash
npx -y traceroot-cli@latest setup --host "http://localhost:8000" --auth-host "http://localhost:3000"
```

Use origins only, without `/api/v1`. If the API and the web app share one origin, `--host` alone is enough. Your deployment's **Traces** page shows this command with its own origins filled in. See [Self-Hosting](/developer/self-hosting) to run a deployment.

## Set up manually

These are the steps setup automates.

### 1. Get an API key

Create an API key either with [TraceRoot Cloud](https://app.traceroot.ai) or [Self-Hosting](/developer/self-hosting).

### 2. Install the SDK

<Tabs>
  <Tab title="Python">
    ```bash
    pip install traceroot
    ```
  </Tab>
  <Tab title="TypeScript">
    ```bash
    npm install @traceroot-ai/traceroot
    ```
  </Tab>
</Tabs>

### 3. Set environment variables

<Frame caption="Tracing setup: sidebar, Manual tab, API key field, Generate button">
  <img src="/images/tracing_api_key_v1.png" alt="TraceRoot Tracing page with the Create an API key step highlighted" />
</Frame>

Neither SDK loads `.env` files automatically; both read the process environment. Export the variables in your shell:

```bash
export TRACEROOT_API_KEY="your-api-key"
export TRACEROOT_HOST_URL="https://app.traceroot.ai"  # self-hosted: your API's origin, e.g. http://localhost:8000
```

*(If you prefer to use a `.env` file, ensure you load it explicitly in your code as shown in the next step.)*

### 4. Instrument your code

<Tabs>
  <Tab title="Python">
    Initialize TraceRoot where your application starts, inside the `if __name__ == "__main__":` block rather than at module scope, so a test that imports the module doesn't send traces.

    ```python
    import traceroot
    from traceroot import Integration
    from openai import OpenAI

    def main():
        client = OpenAI()
        # ...your application

    if __name__ == "__main__":
        # from dotenv import load_dotenv; load_dotenv()  # Uncomment if using a .env file (requires: pip install python-dotenv)
        traceroot.initialize(integrations=[Integration.OPENAI])  # instruments all OpenAI calls
        main()
    ```

    If a server such as uvicorn or gunicorn imports your module instead of running it, that block never runs, so initialize where the framework starts up instead.
  </Tab>
  <Tab title="TypeScript">
    Initialize TraceRoot in the function your entry point calls to start, rather than at module scope, so a test that imports the module doesn't send traces.

    ```typescript
    // import { config } from 'dotenv';  // Uncomment if using a .env file (requires: npm install dotenv)
    import OpenAI from 'openai';
    import { TraceRoot } from '@traceroot-ai/traceroot';

    // The function your entry point calls to start the application
    async function main() {
      // config();
      TraceRoot.initialize({ instrumentModules: { openAI: OpenAI } });  // instruments all OpenAI calls
      const openai = new OpenAI();
      // ...your application
    }
    ```

    If a framework loads your module instead of running it, initialize where the framework starts up instead.
  </Tab>
</Tabs>

Run your own tests with `TRACEROOT_ENABLED=false` so they don't send traces either. For full SDK details, see the [Python SDK](/tracing/python-sdk) or [TypeScript SDK](/tracing/typescript-sdk).

### 5. See your first trace

Run your application and exercise the code you instrumented. Open [TraceRoot Cloud](https://app.traceroot.ai) (or your self-hosted dashboard), navigate to your project, and you'll see the full span hierarchy, token usage, cost, and timing.

Prefer the terminal? The [TraceRoot CLI](/cli/get-started) lists, inspects, and exports the same traces without leaving your shell.

## Troubleshoot

### Setup stopped partway

Ask setup what went wrong, then continue from where it stopped:

```bash
npx -y traceroot-cli@latest setup doctor
npx -y traceroot-cli@latest setup --resume
```

If you ran setup with `--service <path>`, pass the same option to both. If your coding agent didn't finish, setup keeps its output in `.traceroot/setup-instrument-output.log`. That file can quote your repository's files, secrets included, so check it before you share it.

### No trace arrived

Run your application once and exercise the instrumented code, then run `npx -y traceroot-cli@latest setup --resume`. Neither SDK loads `.env` on its own, so check that your application loads the file setup wrote, or export the variables in your shell.

Ask on [Discord](https://discord.gg/TM2m3CtKuC) or [open an issue](https://github.com/traceroot-ai/traceroot-cli/issues).
