title: Cost Tracking
description: Automatic token counting and cost calculation for LLM calls

TraceRoot captures token usage from instrumented LLM calls and calculates cost using its built-in pricing catalog, workspace-configured custom model pricing, or direct caller-supplied costs.

<Tabs>
  <Tab title="Python">
    ```python
    import traceroot
    from traceroot import Integration
    from openai import OpenAI

    traceroot.initialize(integrations=[Integration.OPENAI])
    client = OpenAI()

    # OpenAI calls are tracked automatically; cost requires a priced model ID
    client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": "Hello"}]
    )
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import OpenAI from 'openai';
    import { TraceRoot } from '@traceroot-ai/traceroot';

    TraceRoot.initialize({ instrumentModules: { openAI: OpenAI } });
    const client = new OpenAI();

    // OpenAI calls are tracked automatically; cost requires a priced model ID
    await client.chat.completions.create({
      model: 'gpt-4o',
      messages: [{ role: 'user', content: 'Hello' }],
    });
    ```
  </Tab>
</Tabs>

## How It Works

1. **Auto-instrumentation** — TraceRoot integrations capture token usage from the provider response automatically.
2. **Fallback estimation** — When token counts aren't in the response, TraceRoot estimates using tiktoken.
3. **Model matching** — The reported model ID is matched against TraceRoot's pricing table, including supported provider-prefixed and hosted aliases.
4. **Cost calculation** — When a match exists, token counts are multiplied by that entry's prices. For unpriced models or custom rates, cost can be calculated via **Workspace Custom Model Pricing** or supplied directly on the span.

## Pricing coverage

Pricing entries currently cover these model families:

- OpenAI
- Anthropic, including supported model IDs routed through Amazon Bedrock and Claude 3.x model IDs on Google Vertex AI
- Google Gemini
- xAI
- DeepSeek
- Moonshot (Kimi)
- Z.AI (GLM)
- TypeSafe AI (JEV)

Coverage is based on model-ID patterns, not merely the provider or integration name. Notable model families without pricing entries include Mistral, Groq-hosted models, Amazon Nova and Titan, and Meta Llama. Routed models, such as models called through OpenRouter or Bedrock, are priced only when the routed model ID matches a pricing entry.

## What Gets Tracked

Each LLM span captures:

| Metric | Description |
|--------|-------------|
| Input tokens | Tokens in the prompt/messages |
| Output tokens | Tokens in the completion/response |
| Total tokens | Sum of input and output |
| Cost (USD) | Calculated via catalog pricing, workspace custom pricing, or caller-supplied span cost |

## Custom and Caller-Supplied Pricing

For models not in TraceRoot's standard catalog (brand-new releases, fine-tunes, self-hosted deployments, or negotiated enterprise rates), you can supply costs in two ways:

### 1. Workspace Custom Model Pricing

You can register prices once in **Workspace Settings > Model Pricing** without modifying application code:
- Define prices per million tokens ($/1M) for input, output, cache read, and cache write.
- Match models by exact identifier or regex pattern (e.g. `^meta-llama/.*`).
- Custom pricing applies to all future spans ingested within the workspace.

### 2. Caller- and Instrumentor-Supplied Span Costs

If your application, gateway, or instrumentation SDK already knows the billed cost, send it directly on the span using standard OpenTelemetry attributes:
- `claude_agent_sdk.total_cost_usd` (Anthropic Claude Agent SDK)
- `gen_ai.usage.cost` (OpenTelemetry GenAI Semantic Conventions)
- `llm.cost.total` (OpenInference Semantic Conventions)
- `traceroot.llm.cost` (TraceRoot native attribute)

### Pricing Precedence Order

When TraceRoot processes an ingested span, it resolves the cost using this hierarchy:
1. **Supplied span cost**: If a caller or instrumentor provides a valid cost directly on the span.
2. **Workspace custom price**: If a custom model rate is registered for the workspace matching the model ID.
3. **TraceRoot catalog price**: Built-in standard model rates.
4. **Fallback token estimation**: When provider token counts are missing, token usage is estimated and cost is calculated using matching model pricing if available.

## Manual Token Reporting

For custom or unsupported providers, report token usage manually:

<Tabs>
  <Tab title="Python">
    ```python
    from traceroot import observe, update_current_span

    class MockLLM:
        def generate(self, prompt):
            class Response:
                text = "mock response"
                input_token_count = 10
                output_token_count = 20
            return Response()

    my_llm = MockLLM()

    @observe(name="custom_llm", type="llm")
    def call_custom_llm(prompt: str):
        response = my_llm.generate(prompt)

        update_current_span(
            model="claude-opus-5",
            usage={
                "input_tokens": response.input_token_count,
                "output_tokens": response.output_token_count,
            },
        )

        return response.text
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { observe, updateCurrentSpan } from '@traceroot-ai/traceroot';

    const myLlm = {
      generate: async (prompt: string) => ({
        text: 'mock response',
        inputTokenCount: 10,
        outputTokenCount: 20,
      }),
    };

    const result = await observe({ name: 'custom_llm', type: 'llm' }, async () => {
      const prompt = "hello";
      const response = await myLlm.generate(prompt);

      updateCurrentSpan({
        model: 'claude-opus-5',
        usage: {
          input: response.inputTokenCount,
          output: response.outputTokenCount,
        },
      });

      return response.text;
    });
    ```
  </Tab>
</Tabs>

<Note>
  **Usage keys differ by language:**
  In Python, use `input_tokens` and `output_tokens` (and `reasoning_tokens`, `cache_read_tokens`, `cache_write_tokens`).
  In TypeScript, use `input`, `output`, `cacheRead`, `cacheWrite`, and `total`.
</Note>
