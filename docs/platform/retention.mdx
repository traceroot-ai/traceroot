TraceRoot automatically manages query access to your telemetry in ClickHouse. Traces and spans are queryable only within the retention window, after which out-of-window reads are clamped or rejected.

## Plan retention defaults

Every TraceRoot subscription plan includes a default retention period:

| Plan | Default Retention | Best For |
| :--- | :--- | :--- |
| **Free** | **15 days** | Prototyping, testing, and hobbyist projects. |
| **Starter** | **30 days** | Standard monthly production tracking and triage. |
| **Pro** | **90 days** | Multi-month trend analysis, quarterly reviews, and regression testing. |
| **Enterprise** | **Custom** | Workspaces that need a custom retention window. |

## Configuring per-project retention (`trace_ttl_days`)

A project carries a `trace_ttl_days` field intended to override the plan baseline per project.

<Warning>
  `trace_ttl_days` is stored but not yet enforced. The query window is gated on the billing plan alone — `clamp_retention_window` reads the plan's retention days, and no read, clamp or delete path consults `trace_ttl_days`. Setting it does not move the window described under [Query window clamping](#query-window-clamping).
</Warning>

The field accepts an integer between **1 and 365 days**, and passing `null` resets the project's retention back to the workspace plan default. Changing project retention requires the **ADMIN** role in the project's workspace. `PATCH /api/v1/public/projects/{id}` is user-only: a project API key (`tr-` prefix) is rejected with `403`, so these calls need a user session token or a CLI access JWT.

## Query window clamping

When querying telemetry through the REST API, dashboards, or widgets, requested time ranges are compared against your retention window:

- If you query a time window whose start date extends earlier than your retention boundary, TraceRoot automatically clamps the query's `start_time` forward to the retention limit.
- The returned `QueryWindow` object sets `clamped: true`:

```json
{
  "window": {
    "start_time": "2026-09-02T00:00:00Z",
    "end_time": "2026-10-02T00:00:00Z",
    "range": "30d",
    "clamped": true
  }
}
```

This prevents queries from failing or returning inaccurate partial aggregates without explanation.
