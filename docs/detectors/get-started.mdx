Detectors evaluate your traces and surface problems the moment they happen. This guide walks through creating your first detector, watching the LLM-as-a-judge flag a problem, and reading the AI agent's root cause analysis.

## Prerequisites

You need a project with at least one incoming trace. See [Tracing](/tracing/get-started) if you don't have that yet.

## Create a detector

Open your project in [TraceRoot Cloud](https://app.traceroot.ai), select **Detectors** from the left nav, then click **+ New Detector**.


### Pick a starting point

The create sheet offers six templates: **Failure**, **Hallucination**, **Logic Error**, **Task Completion**, **Safety**, and **Blank**. Pick whichever maps to a problem you've seen in production. The template fills in a prompt you can edit; save, and the detector starts considering new incoming traces.

### Choose a sample rate

New detectors evaluate **25%** of the traces that match their trigger conditions. Sampling is deterministic for each trace and detector, so sending the same trace again does not change the decision. Set the rate to **100%** to evaluate every matching trace, or to **0%** to pause the detector.

### Choose whether to run root cause analysis

The create sheet — and the edit panel for an existing detector — includes a **Run root cause analysis on findings** toggle, on by default. Leave it on and the AI agent investigates each new signal (a recurring problem the detector's findings are grouped into); turn it off for a noisy or low-stakes detector where you want findings recorded without paying agent-model cost. Detection and notifications are unaffected either way: the detector still fires, records findings and announces new signals.

RCA runs per signal, not per finding: a new signal gets an analysis, and so does a signal reopened more than 24 hours after its last one. See [Root cause analysis](/detectors/introduction#root-cause-analysis) for the exact rule.

## How it works

The pipeline for each incoming trace:

1. **Ingest.** A trace lands in the project.
2. **Match.** TraceRoot checks each enabled detector's trigger conditions.
3. **Sample.** Each matching detector applies its sample rate; new detectors default to 25%.
4. **Evaluate.** The LLM-as-a-judge (Claude Haiku by default) reads the sampled trace and returns `identified` plus a short summary.
5. **Diagnose.** When `identified` is true, the trace becomes a **finding** and joins a signal. When it starts a new signal (or reopens a resolved one) and its detector has **Run root cause analysis on findings** enabled, the TraceRoot AI agent investigates: it downloads the trace, reads your production source code at the failure point, checks recent commits and PRs touching that file, and produces a root cause analysis.
6. **Notify.** At the end of the configured window, TraceRoot sends one digest to each configured email and Slack channel announcing new and reopened signals. Further findings on an open signal send nothing. Each signal shows its title, a short summary, its detector and hit count, and a link; root cause analysis results stay on the signal page, so the digest never waits for them.


## View findings

Open the detector to see its findings table. Each row links back to the trace that produced it; clicking the trace opens the trace viewer with a red **Alert** badge in the header.

The Alert badge in the trace viewer opens a chat panel pre-loaded with the AI agent's RCA session. From there you can ask follow-up questions in the same session — you're talking to the same agent that wrote the analysis.

## Bring Your Own Key (BYOK)

Both stages of the pipeline — the LLM-as-a-judge and the AI agent — run on a model you choose. Either can use a TraceRoot-provided system model or your own API key, configured independently per stage.
