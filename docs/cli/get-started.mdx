The TraceRoot CLI wraps the TraceRoot API so you can work with your project directly from the terminal — list, inspect, and export traces, then pipe the JSON into whatever comes next. It is built for AI coding agents and power users who prefer the command line.

Full source and reference live in the [`traceroot-cli`](https://github.com/traceroot-ai/traceroot-cli) repo.

## Install

```bash
npm install -g traceroot-cli
```

## Authenticate

The CLI authenticates with either a **browser login** (the default interactive device flow) or a **project API key** (for CI environments and scripts).

### Browser login (default)

Run `traceroot login` to sign in through your browser:

```bash
traceroot login
```

This initiates an OAuth device flow (RFC 8628), opens your browser to authorize access, and saves a session credential to `~/.config/traceroot/credentials.json`. The session token is automatically refreshed before each request.

### API key login (CI & scripts)

For CI pipelines, automated scripts, or headless environments, use a project API key (`tr-...`):

```bash
traceroot login --api-key tr-...
```

This validates the key against the API and saves it to `./.traceroot/config.json`.

You can also pass credentials using environment variables, `--env-file`, or an auto-discovered `./.env` file:

```bash .env
TRACEROOT_API_KEY=tr-...
TRACEROOT_HOST_URL=https://app.traceroot.ai
```

The CLI resolves credentials in this order:
1. `--api-key` flag
2. `--env-file <path>`
3. `TRACEROOT_TOKEN` environment variable
4. Credentials file (`~/.config/traceroot/credentials.json`)
5. `TRACEROOT_API_KEY` environment variable
6. Config file (`./.traceroot/config.json`)
7. Auto-discovered `./.env`

<Note>
Because the CLI automatically discovers and loads `./.env`, having `TRACEROOT_API_KEY` in your `./.env` will automatically select key mode.
</Note>

Create API keys in [TraceRoot Cloud](https://app.traceroot.ai) or your [self-hosted](/developer/self-hosting) dashboard.

### Verify credentials

Confirm your active identity:

```bash
traceroot status
```

- **Browser login**: Displays your authenticated email address, host URL, active project (or a hint to select one), and accessible workspaces.
- **API key login**: Displays your workspace, project, host URL, and a masked key hint (e.g. `tr-d0a3-…-57e3`).

## Scope to a project

A browser login identifies *you* across your workspaces rather than binding to a single project. Because commands such as `traces` and `evals` are project-scoped, you must select a project before running them. (If you authenticated with an API key, your key is already scoped to a specific project and this step is not needed.)

1. List the projects you can access to find your project ID:

```bash
traceroot projects list
```

2. Set `TRACEROOT_PROJECT_ID` so subsequent commands run without extra flags:

```bash
export TRACEROOT_PROJECT_ID=<project-id>
```

Alternatively, you can pass `--project <id>` to individual commands.

## Inspect and export traces

Once authenticated and scoped to a project, list, inspect, and export traces:

```bash
# List recent traces, newest first (filter by time with --since, --from, or --to)
traceroot traces list --limit 10

# Inspect one trace: header, duration, span tree, and web app link
traceroot traces get <trace-id>

# Fetch full trace details including span inputs, outputs, and metadata as JSON
traceroot traces get <trace-id> --fields full --json

# Write a full trace bundle to disk to share or feed into another tool
traceroot traces export <trace-id> --output ./my-trace
```

### Trace projections and field groups (`--fields`)

By default, `traceroot traces get` prints the trace header, an optional detector finding block, the span tree, and the web app URL.

When emitting JSON (`--json`), `traceroot traces get` defaults to the lightweight `skeleton` projection, leaving span `input`, `output`, and `metadata` as `null` to minimize payload size. Pass `--fields` to include specific data groups:

- **Field groups**: `core`, `usage`, `io`, `metadata`
- **Aliases**: `skeleton` (`core,usage`) and `full` (`core,usage,io,metadata`)

For example, pass `--fields full` (or `--fields io,metadata`) to include span I/O in the JSON payload:

```bash
traceroot traces get <trace-id> --fields full --json
```

In contrast, `traceroot traces export` defaults to the `full` projection, writing `trace.json`, `spans.json`, `git_context.json`, `manifest.json`, and `finding.json` (if flagged by a detector) into the destination directory. Pass `--fields <groups>` to narrow what is exported.

## Read evaluations

The CLI also reads your offline [evaluations](/evals/introduction) — the datasets you run against and the runs that scored them, so a run id no longer has to come from the web app.

```bash
# Which evaluations exist, and how each one's latest run ended
traceroot evals list

# One evaluation's runs, newest first — the RUN ID column is what you read next
traceroot evals runs list --evaluation-id <evaluation-id>

# One run: its counts, per-scorer means, and per-case cost and duration
traceroot evals runs get <run-id>
```

See [From the terminal](/evals/cli) for what each read shows, and for the dataset commands.

## Command reference

Add `--json` to any command for machine-readable output, or run `traceroot <command> --help` for the full flag list.

| Command | What it does |
| :-- | :-- |
| `login` | Sign in with your browser (device flow) and store session credentials. Pass `--api-key <key>` to validate and save an API key instead. |
| `status` | Show the identity your credentials resolve to — email, host, project, and workspaces (browser login) or workspace, project, host, and key hint (API key). |
| `projects list` | List accessible projects across workspaces; the `PROJECT ID` column is what `--project` and `TRACEROOT_PROJECT_ID` take. Flag: `--workspace-id <id>`. |
| `traces list` | List traces for your project, newest first. Flags: `--limit <n>`, `--since <dur>`, `--from <time>`, `--to <time>`. |
| `traces get <id>` | Show one trace: header, span tree, duration, and link to open in TraceRoot. Defaults to the `skeleton` projection (no span I/O); pass `--fields full` (or groups `core`, `usage`, `io`, `metadata`) for span data. Flag: `--fields <groups>`. |
| `traces export <id>` | Write `trace.json`, `spans.json`, `git_context.json`, `manifest.json`, and `finding.json` (if flagged) to a directory. Defaults to `full` projection. Flags: `--output <dir>`, `--force`, `--fields <groups>`. |
| `datasets list` | List the project's evaluation datasets, newest first. Flags: `--limit <n>`, `--name <substring>`. |
| `datasets get <dataset-id>` | Show one dataset and the version its cases are read from. |
| `datasets versions list <dataset-id>` | List a dataset's published versions with their case counts. Flag: `--limit <n>`. |
| `datasets versions get <version-id>` | Show one version and a page of its cases. Flag: `--limit <n>` — 200 by default, up to 1000. |
| `evals list` | List evaluations with their run count and latest run. Flags: `--limit <n>`, `--name <substring>`. |
| `evals runs list` | List evaluation runs, newest first. Flags: `--limit <n>`, `--evaluation-id <id>`, `--status <status>`. |
| `evals runs get <run-id>` | Show one run: counts, per-scorer means, per-case cost and duration, and its URL. |
