The TraceRoot CLI wraps the TraceRoot API so you can work with your project directly from the terminal — list, inspect, and export traces, run analytical queries, and pipe the output into downstream tools.

## 1. Install

Install the CLI globally with `npm` (or run ad-hoc with `npx traceroot-cli`):

```bash
npm install -g traceroot-cli
```

Verify that the `traceroot` executable is installed:

```bash
traceroot --version
```

## 2. Authenticate

Authenticate using either your browser or a project API key:

<Tabs>
  <Tab title="Browser Login (Interactive)">
    ```bash
    traceroot login
    ```
    This launches a device login flow in your default browser. Once authorized, a session credential is saved to `~/.config/traceroot/credentials.json`.
  </Tab>
  <Tab title="API Key (CI & Automation)">
    ```bash
    traceroot login --api-key tr-d0a3ee92-659e-4f63-ae11-8ca6f57657e3
    ```
    This validates your API key against the server and saves it to `./.traceroot/config.json`.

    Alternatively, you can export environment variables without running `login`:
    ```bash
    export TRACEROOT_API_KEY="tr-d0a3ee92-659e-4f63-ae11-8ca6f57657e3"
    export TRACEROOT_HOST_URL="https://app.traceroot.ai"
    ```
  </Tab>
</Tabs>

## 3. Verify identity and status

Confirm which identity, host, and project your credentials resolve to:

```bash
traceroot status
```

Example output for a browser login:

```text
Logged in as:  user@example.com
Credential:    session (browser login)
Host:          https://app.traceroot.ai
Project:       (none — pass --project or run traceroot projects list)
Workspaces:    Acme Corp Engineering (3e5a9d12-4b78-4c61-9f20-8a7b6c5d4e31)
Config source: ~/.config/traceroot/credentials.json
```

## 4. Find your project ID

If you logged in via a browser session, commands that read project data require a project ID. Find your available project IDs:

```bash
traceroot projects list
```

```text
NAME            WORKSPACE              PROJECT ID
Support Bot     Acme Corp Engineering  fa126572-3d41-4c0e-9a6b-1e8d7c2b5f40
Coding Copilot  Acme Corp Engineering  7c91b8e4-52a7-4f3d-8b10-9d6e4a1c3f27
```

Set `TRACEROOT_PROJECT_ID` in your environment (or pass `--project <id>`) so you don't need to specify it for every command:

```bash
export TRACEROOT_PROJECT_ID="fa126572-3d41-4c0e-9a6b-1e8d7c2b5f40"
```

If you authenticated using an API key (`tr-...`), the key is already scoped to a single project, so specifying `--project` is unnecessary.

## 5. Inspect and export traces

### List recent traces

List the latest traces for your project, newest first:

```bash
traceroot traces list --limit 10
```

### Inspect a single trace

View the span tree, duration, and metadata for a specific trace:

```bash
traceroot traces get <trace-id>
```

By default, this renders a lightweight span tree skeleton. Full span input, output, and metadata are only emitted on the `--json` branch, so request them together:

```bash
traceroot traces get <trace-id> --fields full --json
```

### Export a trace bundle

Export a complete trace bundle to disk as JSON files for offline analysis:

```bash
traceroot traces export <trace-id> --output ./exported-trace
```

This creates a directory containing `trace.json`, `spans.json`, `git_context.json`, and `manifest.json`.

## 6. Read evaluations

The CLI also reads your offline [evaluations](/evals/introduction) — the datasets you run against and the runs that scored them, so a run id no longer has to come from the web app:

```bash
# Which evaluations exist, and how each one's latest run ended
traceroot evals list

# One evaluation's runs, newest first — the RUN ID column is what you read next
traceroot evals runs list --evaluation-id <evaluation-id>

# One run: its counts, per-scorer means, and per-case cost and duration
traceroot evals runs get <run-id>
```

See [From the terminal](/evals/cli) for what each read shows, and for the dataset commands.
