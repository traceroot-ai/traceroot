The traceroot CLI sets up tracing in your repository with one command, then lets you work with your project from the terminal: traces, detector findings, alerts, dashboards, evaluations, and SQL. Pipe the JSON into whatever comes next. It is built for AI coding agents and power users who prefer the command line.

The source is in the [`traceroot-cli`](https://github.com/traceroot-ai/traceroot-cli) repo.

## Set up a repository

Run this from the root of the repository you want to trace:

```bash
npx -y traceroot-cli@latest setup
```

Setup signs you in, has your coding agent add the traceroot SDK, and waits for your first trace; no install or sign-in needed first. [Tracing](/tracing/get-started) covers each step, self-hosting, and troubleshooting.

### Run without prompts

Setup never prompts when it isn't attached to a terminal, when `CI` is set to anything but empty or `false`, or with `--no-input` or `--json`. Pass what it would otherwise ask for:

```bash
npx -y traceroot-cli@latest setup --no-input --api-key "$TRACEROOT_API_KEY"
```

A project API key also sets the project. Without a key, run `npx -y traceroot-cli@latest login` first, then run setup without `--api-key`. Login prints a URL and a code for a person to confirm in a browser, and waits, so a coding agent has to show them to you. If setup exits 10, it can't choose for you, usually because you have several projects or none: follow the remedy it prints. With several projects, you can pass `--project`.

Without prompts, setup notes uncommitted changes instead of asking, and writes the instrumentation task to `.traceroot/prompts/setup-instrument.md` rather than running a coding agent. Pass `--agent claude` or `--agent codex` to run one. After the task is done and the application has run, rerun the same setup command with `--resume`, such as `npx -y traceroot-cli@latest setup --no-input --resume`, to get a link to the first trace. [Exit codes](/cli/scripting#exit-codes) lists what each code means, and [Coding agents](/getting-started/coding-agents#set-up-tracing) has these steps as a prompt.

## Install

Every command also runs through `npx`, as above. To keep the `traceroot` command, install the CLI globally:

```bash
npm install -g traceroot-cli
```

The examples below use `traceroot`. Without a global install, replace it with `npx -y traceroot-cli@latest`.

The CLI needs Node.js 20.3 or later, and `setup` needs 20.12 or later.

## Authenticate

The CLI authenticates with either a **browser login** (the default interactive device flow) or a **project API key** (for CI environments and scripts).

### Browser login (default)

Run `traceroot login` to sign in through your browser:

```bash
traceroot login
```

It prints a URL and a code, tries to open your browser, and saves a session to `~/.config/traceroot/credentials.json`. If no browser opens, open the URL yourself. A key or saved credential [changes what `login` does](/cli/authentication#what-login-does).

### API key login (CI & scripts)

For CI pipelines, automated scripts, or headless environments, use a project API key (`tr-...`):

```bash
traceroot login --api-key tr-...
```

This validates the key against the API and saves it to `./.traceroot/config.json`.

Or set `TRACEROOT_API_KEY`, which a saved browser login [outranks](/cli/authentication#which-credential-is-used). A project API key [can't create or change resources](/cli/authentication#browser-login-and-api-keys).

Create API keys in [traceroot Cloud](https://app.traceroot.ai) or your [self-hosted](/developer/self-hosting) dashboard.

### Verify credentials

Confirm your active identity:

```bash
traceroot status
```

- **Browser login**: Displays your authenticated email address, host URL, active project (or a hint to select one), and accessible workspaces.
- **API key login**: Displays your workspace, project, host URL, and a masked key hint (e.g. `tr-d0a3-57e3`).

## Scope to a project

A browser login identifies you across your workspaces rather than binding to one project, and commands such as `traces` and `evals` are project-scoped, so pick a project first. An API key is already scoped to its project, so a key login can skip this step.

List the projects you can access to find your project ID:

```bash
traceroot projects list
```

Set `TRACEROOT_PROJECT_ID` so later commands need no extra flags, or pass `--project <id>` to individual commands:

```bash
export TRACEROOT_PROJECT_ID=<project-id>
```

[Choose a project](/cli/authentication#choose-a-project) has the full order.

## Inspect and export traces

Once authenticated and scoped to a project, list, inspect, and export traces:

```bash
# Recent traces
traceroot traces list --limit 10

# One trace as JSON, with span I/O
traceroot traces get <trace-id> --fields full --json

# A trace bundle on disk
traceroot traces export <trace-id> --output ./my-trace
```

[Traces](/cli/traces) covers time filters, field groups, and the exported files.
