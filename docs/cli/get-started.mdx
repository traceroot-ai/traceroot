The TraceRoot CLI wraps the TraceRoot API so you can work with your project directly from the terminal — list, inspect, and export traces, then pipe the JSON into whatever comes next. It is built for AI coding agents and power users who prefer the command line.

Full source and reference live in the [`traceroot-cli`](https://github.com/traceroot-ai/traceroot-cli) repo.

## Install

```bash
npm install -g traceroot-cli
```

## Authenticate

```bash
traceroot login
```

This validates your project API key and saves it locally, so later commands need no flags. Create API keys in [TraceRoot Cloud](https://app.traceroot.ai) or your [self-hosted](/developer/self-hosting) dashboard.

For CI or scripts, set environment variables instead — the same ones the SDKs use:

```bash .env
TRACEROOT_API_KEY=tr_...
TRACEROOT_HOST_URL=https://app.traceroot.ai
```

Confirm the credentials resolve to the right place:

```bash
traceroot status
```

## Inspect and export traces

```bash
# List recent traces, newest first
traceroot traces list --limit 10

# Inspect one: span tree, duration, I/O preview, and a link to open it in TraceRoot
traceroot traces get <trace-id>

# Write a full trace bundle to disk to share or feed into another tool
traceroot traces export <trace-id> --output ./my-trace
```

## Read evaluations

The CLI also reads your offline [evaluations](/evals/introduction) — the datasets you run against and the runs that scored them, so a run id no longer has to come from the web app.

```bash
# Which evaluations exist, and how each one's latest run ended
traceroot evals list

# One evaluation's runs, newest first — the RUN ID column is what you read next
traceroot evals runs list --evaluation-id <evaluation-id>

# One run: its counts, per-scorer means, and per-case cost and duration
traceroot evals runs get <run-id>
```

See [From the terminal](/evals/cli) for what each read shows, and for the dataset commands.

## Command reference

Add `--json` to any command for machine-readable output, or run `traceroot <command> --help` for the full flag list.

<!-- [start:cli-commands] -->

| Command | Description |
| :--- | :--- |
| `login` | Validate an API key or authenticate with browser and save credentials. |
| `logout` | Revoke the session server-side (best-effort) and remove the local credential. |
| `status` | Show the identity your credentials resolve to — workspace, project, host, and key hint. |
| `doctor` | Check local environment, dependencies, configuration, and API connectivity. |
| `instrument` | Auto-instrument your codebase for OpenTelemetry tracing. |
| `skills list` | List available AI agent skills and their capabilities. |
| `skills install` | Install skills into your coding agent workspace. |
| `traces list` | List recent traces for the caller's project (newest first). (Flags: `--limit`, `--name`) |
| `traces get <id>` | Get a single trace for the caller's project. |
| `traces export <id>` | Export the V1 bundle (trace + spans + git_context + manifest) for the caller's project. |
| `detectors list` | List the detectors in the caller's project (newest first). (Flags: `--limit`) |
| `detectors get <id>` | Get one detector's full configuration for the key's project. |
| `findings list` | List recent detector findings for the caller's project (newest first). (Flags: `--limit`) |
| `findings get <finding-id>` | Get a single finding by id for the key's project. |
| `alerts list` | List the alerts in the caller's project (oldest first) with its capacity. (Flags: `--limit`, `--page`) |
| `alerts get <id>` | Get one alert with its full rule for the caller's project. |
| `alerts create` | Create a threshold alert in a project the authenticated user can write to. |
| `alerts update <id>` | Edit an alert's rule in a project the authenticated user can write to. |
| `alerts status <id>` | Pause or resume an alert without touching its rule. |
| `alerts delete <id>` | Hard-delete an alert. |
| `dashboards list` | List the dashboards in the caller's project (default first). |
| `dashboards get <id>` | Get one dashboard with its widgets for the caller's project. |
| `dashboards create` | Create a dashboard in a project the authenticated user can write to. |
| `dashboards update <id>` | Edit a dashboard's name or description. |
| `dashboards delete <id>` | Hard-delete a dashboard together with its widgets. |
| `workspaces list` | List the workspaces the authenticated user belongs to. |
| `projects list` | List the projects the authenticated user can access, across workspaces. |
| `workspaces create` | Create a workspace administered by the authenticated user. |
| `workspaces update <workspace-id>` | Rename a workspace the authenticated user administers. |
| `workspaces delete <workspace-id>` | Hard-delete a workspace and everything in it. (Flags: `--name`) |
| `projects create` | Create a project in a workspace the authenticated user can write to. |
| `projects update <project-id>` | Edit a project's name or trace retention. |
| `projects delete <project-id>` | Soft-delete a project. |
| `detectors create` | Create a detector in a project the authenticated user can write to. |
| `detectors update <id>` | Edit a detector in a project the authenticated user can write to. |
| `detectors delete <id>` | Hard-delete a detector; its existing findings stay readable. |
| `widgets get <id>` | Get one saved widget's definition, with its dashboard, for the caller's project. |
| `widgets data <id>` | Answer one saved widget for a window, with a status instead of an exception. (Flags: `--range`) |
| `widgets create` | Create a widget on a dashboard the authenticated user can write to. |
| `widgets update <id>` | Edit a widget's title, spec, or display config. |
| `widgets delete <id>` | Hard-delete a widget and its entry in the dashboard's layout. |
| `sql` | Run one read-only SQL query scoped to the caller's project. |
| `sql schema` | Return the curated tables and columns available to public SQL. |
| `datasets list` | List datasets, newest first. (Flags: `--limit`, `--name`) |
| `datasets get <dataset-id>` | Read one dataset. |
| `datasets versions list <dataset-id>` | List versions newest-first, each with its case count and whether it is current. (Flags: `--limit`) |
| `datasets versions get <version-id>` | Read an immutable snapshot: the version plus its cases, whole or a page at a time. (Flags: `--limit`) |
| `evals list` | List evaluations, newest first, each with its run count and latest run. (Flags: `--limit`, `--name`) |
| `evals runs list` | List evaluation runs, newest first, optionally one evaluation's or one status's. (Flags: `--limit`, `--evaluation-id`, `--status`) |
| `evals runs get <id>` | Read a run's own summary: status, result counts, and per-score and per-metric. |
