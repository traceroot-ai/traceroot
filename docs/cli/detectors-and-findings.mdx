title: Detectors & Findings
description: Manage automated failure detectors and review root-cause analysis findings
---

TraceRoot detectors continuously evaluate execution traces for anomalies, model hallucinations, tool errors, regressions, and guardrail violations. When an issue is identified, a **finding** is produced with automated Root Cause Analysis (RCA).

## Detectors

### `traceroot detectors list`

List all detectors configured in your project.

```bash
traceroot detectors list [options]
```

#### Flags

| Flag | Type | Description |
| :--- | :--- | :--- |
| `--limit <n>` | number | Maximum number of detectors to return |
| `--since <duration>` | string | Filter detectors updated within a duration (e.g. `24h`, `7d`) |
| `--project <id>` | string | Project ID (required when using browser login) |
| `--json` | boolean | Output raw JSON records |

```bash
# List all detectors
traceroot detectors list

# Extract detector IDs with jq
traceroot detectors list --json | jq -r '.data[].detector_id'
```

---

### `traceroot detectors get <id>`

Inspect the full definition, prompt, sample rate, and status of a specific detector.

```bash
traceroot detectors get <detector-id> [options]
```

```bash
traceroot detectors get det_5f8b9e1a2c3d4e5f
```

---

### `traceroot detectors create`

Create a new detector. Write commands accept a JSON definition via `--from-file <path>` (or `-` for stdin), with optional flags overriding individual fields.

```bash
traceroot detectors create --from-file <path> [options]
```

#### Flags

| Flag | Type | Description |
| :--- | :--- | :--- |
| `--from-file <path>` | string | Path to JSON file (or `-` for stdin) defining the detector |
| `--name <string>` | string | Name of the detector |
| `--template <string>` | string | Template key (e.g. `tool-call-failure`, `hallucination`) |
| `--prompt <string>` | string | LLM evaluation prompt or rule specification |
| `--project <id>` | string | Project ID (required when using browser login) |

#### Example

Create a definition file `detector.json`:

```json
{
  "name": "SQL Injection Detection",
  "template": "security_check",
  "prompt": "Evaluate whether any tool call contains unsanitized SQL syntax or injection risks.",
  "enabled": true,
  "sample_rate": 100
}
```

Deploy the detector:

```bash
traceroot detectors create --from-file detector.json

# Or pipe directly from stdin
cat detector.json | traceroot detectors create --from-file -
```

---

### `traceroot detectors update <id>`

Update an existing detector's configuration, prompt, or enabled status.

```bash
traceroot detectors update <detector-id> [options]
```

#### Flags

| Flag | Type | Description |
| :--- | :--- | :--- |
| `--from-file <path>` | string | JSON file with updated attributes |
| `--name <string>` | string | New detector name |
| `--prompt <string>` | string | Updated prompt |
| `--enabled <boolean>` | boolean | Enable or disable the detector (`true` / `false`) |
| `--sample-rate <n>` | integer | Evaluation sample percentage (`1` to `100`) |

```bash
# Disable a detector
traceroot detectors update det_5f8b9e1a2c3d4e5f --enabled false
```

---

### `traceroot detectors delete <id>`

Permanently delete a detector. Existing historical findings generated by this detector remain preserved.

```bash
traceroot detectors delete <detector-id> --reason <text>
```

#### Flags

| Flag | Type | Description |
| :--- | :--- | :--- |
| `--reason <text>` | string | *(Required)* Audit justification (3–500 characters) |

```bash
traceroot detectors delete det_5f8b9e1a2c3d4e5f --reason "Deprecated in favor of combined guardrail detector"
```

## Findings

Findings represent detected failures or policy violations associated with specific traces.

### `traceroot findings list`

List findings across traces in your project.

```bash
traceroot findings list [options]
```

#### Flags

| Flag | Type | Description |
| :--- | :--- | :--- |
| `--limit <n>` | number | Maximum number of findings to return |
| `--since <duration>` | string | Filter findings within a duration (e.g. `24h`, `7d`) |
| `--detector <id>` | string | Filter findings produced by a specific detector ID |
| `--trace <id>` | string | Filter findings belonging to a specific trace ID |
| `--project <id>` | string | Project ID (required when using browser login) |
| `--json` | boolean | Output raw JSON data |

```bash
# List recent findings from the past 24 hours
traceroot findings list --since 24h

# List findings for a particular detector
traceroot findings list --detector det_5f8b9e1a2c3d4e5f --limit 50
```

---

### `traceroot findings get [id]`

Show the details of a finding, including per-detector results, severity, and the automated Root Cause Analysis (RCA).

You must specify either the finding ID as an argument or pass `--trace <id>`.

```bash
# Lookup by finding ID
traceroot findings get fnd_8e7d6c5b4a3f2e1d

# Or lookup findings associated with a trace ID
traceroot findings get --trace 99224be337d725fd5e8f2e7b45dc22ef
```

```text
Finding ID:   fnd_8e7d6c5b4a3f2e1d
Severity:     HIGH
Detector:     SQL Injection Detection (det_5f8b9e1a2c3d4e5f)
Trace ID:     99224be337d725fd5e8f2e7b45dc22ef
Created:      2026-10-01T18:24:12Z

ROOT CAUSE ANALYSIS (RCA):
The agent constructed a raw SQL query inside tool call 'execute_sql' by concatenating
the user input without validation:
  query: "SELECT * FROM users WHERE name = '" + user_input + "'"
Input contained a quote break attempt: "admin' OR '1'='1".
Remediation: Use parameterized queries with bind variables in tools/db.py.
```
